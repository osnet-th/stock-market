## 이슈 상세 기반 이해
기존 S-RIM 요구수익률에는 직접 입력만 있다. 여기에 실제 채권 기준수익률을 골라 적용하는 기능을 추가한다. 태형님은 두 가지를 선택했다.
- 국고채와 공모 무보증 회사채 AAA~BBB- 전체를 수집한다.
- 직접 입력과 금리 선택·적용을 함께 쓴다.

## 문제 정의
요구수익률을 외부에서 찾아 수동으로 입력해야 한다. 채권 등급·만기·기준일이 분명한 선택지를 제공하려 한다. 이 값은 특정 기업의 채권 금리가 아니라 시장 기준수익률이다. 등급을 고른다고 해서 그 기업의 신용등급을 판정하는 것은 아니다.

## 목표
- 기업 리포트와 종목 평가의 S-RIM에서 다음 흐름을 제공한다.
  1. 종류·등급·만기를 선택한다.
  2. 기준일과 금리를 확인한다.
  3. 적용 버튼으로 요구수익률을 채운다.
- 기존 S-RIM 계산식과 직접 입력 기능은 유지한다.

## 범위
**조회 대상**
- 국고채 1·3·5·10·20·30년
- 공모 무보증 회사채 AAA, AA+, AA, AA-, A+, A, A-, BBB+, BBB, BBB-
- 회사채 만기는 원본의 15개 만기다: 3·6·9·12·18·24·30·36·48·60·84·120·240·360·600개월. 제공되지 않는 값은 null이다.

**조회와 캐시**
- 요청할 때 조회하고, 기준일별 전체 금리 응답을 Caffeine 메모리 캐시에 보관한다.
- 같은 날짜에서 종류·등급·만기를 바꾸면 캐시에서 돌려준다.
- 같은 날짜로 동시에 들어온 요청은 외부 호출 한 번으로 합친다.

**표시와 오류**
- 데이터 기준일과 출처를 표시하고, 누락된 금리는 선택할 수 없게 한다.
- 외부 오류와 잘못된 응답은 정상 금리로 캐싱하지 않는다.
- 폴백했을 때는 실제 기준일을 반드시 표시한다.

**적용과 대상 통화**
- 적용하면 기존 계산 결과를 무효화하고, 사용자가 명시적으로 재계산한다.

## 권장 접근

- 조회 UI는 캐시가 있으면 바로 돌려주고, 없으면 외부에서 조회한 뒤 캐싱한다. 요구수익률은 사용자가 적용할 때만 바뀐다.

- 최신 기준일 탐색은 금리 응답 캐시와 분리해, 날짜가 한 값에 고정되지 않게 한다.
- 만료·퇴거·서버 재시작 뒤에는 다시 조회한다.
- 금리 DB와 Entity는 추가하지 않는다. 조회 API와 캐시 정책은 plan에서 승인받은 뒤 구현한다.

## 확인된 수집 계약
**요청**
- `GET /vl/valuation01_01/bondRates/maxDate` → 2026-09-28을 확인했다.
- `GET /vl/valuation01_01/bondRates?ymd=20260928&type=Y&searchType=0&lang=kor` → JSON 63행을 확인했다.

**행 식별**
- 국고채: `GMRI_CODE=A101`, `GMRI_TYPE=국채`, `GMRI_SUBTYPE=국고채`
- 공모 무보증 BBB-: `GMRI_CODE=F243`, `GMRI_TYPE=회사채<br>(공모)`, `GMRI_SUBTYPE=무보증`, `GMRI_BOND=BBB-`
- 같은 BBB-가 금융채와 사모회사채에도 있다. 그래서 등급 문자열만으로 매핑하면 안 된다.

**값 규칙**
- 만기 키는 `M036`=3년, `M060`=5년 형식이다. 확인한 응답에서 공모 무보증 BBB-는 3년 10.588%, 5년 10.986%였다.
- `-`와 공백은 정규화하고, 미제공과 숫자 0을 구분한다.
- 원본 단위는 %이고 S-RIM 입력은 소수 단위다. 둘 사이의 변환은 경계에서 명시적으로 한다.

**아직 확인하지 않은 것**
- 이 endpoint는 공개 화면이 쓰는 요청일 뿐이다. 공식 무료 API인지, 자동 수집·재게시가 허가되는지는 확인하지 않았다.
- 과거 날짜의 실제 응답, Excel 파일 구조, 이용 조건은 추가 확인이 필요하다.

## 현재 코드 확인 결과 보완 (2026-09-29)
plan 작성에 영향을 주는 현재 코드 사실과 외부 라이브러리 계약이다.

**S-RIM 입력 전달**
- `SrimInput.requiredReturn`은 소수 `BigDecimal`이다.
- `SrimValidator.positiveRate`는 0보다 클 것을 요구하고, draft가 아니면 필수로 본다.
- 두 화면 모두 `POST /api/company-reports/srim/calculate`를 호출한다. 종목 평가 화면에는 별도 S-RIM 백엔드가 없다.
- S-RIM은 리포트의 nullable `srim` JSONB에 입력과 결과를 저장한다.

**선택 근거 보존 시 영향 범위 (결정 전 검토 내용)**
- 보존하려면 `SrimInputData`·`SrimInput`·JSONB 구조에 필드를 추가해야 한다. 기업 리포트 생성·수정 요청 DTO와 상세 조회 응답도 바뀐다.
- DB 테이블·컬럼 변경은 없다. 하지만 JSONB에 저장되는 구조와 public API가 바뀐다.
- #124는 "출처 표시는 입력 화면에서만, S-RIM JSONB 불변"으로 결정했다. 보존을 택하면 이 결정을 번복하게 된다.
- 종목 평가는 저장 없는 화면이라 어느 쪽을 택해도 화면 표시만 한다.

**화면 구조**
- 요구수익률 입력 위치: `company-report.html:748`, `stock-eval.html:618`
- 두 S-RIM `<section>`에는 섹션 단위 `@input`/`@change`가 있어서 어떤 입력이든 바뀌면 계산 결과를 지운다.
  - 금리 선택 `<select>`는 금액 단위 select 선례(`@change.stop`)를 따르거나 섹션 밖에 두어야 한다.
- 코드로 값을 넣으면 `@input`이 발생하지 않는다. 적용 처리에서 `crSrimChanged()`/`seSrimChanged()`를 직접 호출해야 한다.
- 외화 판정 근거가 이미 있다. 리포트 S-RIM에는 `currency`가 있고, 화면에는 `crSrimCurrencyLabel()`이 있다.

**외부 호출 선례**
- `economics.infrastructure.global.tradingeconomics`가 외부 조회 구조의 선례다.
  - Jsoup를 쓴다.
  - Properties로 timeout·userAgent를 설정한다.
  - Fetch 예외와 Parse 예외를 분리한다.
- 기본 `restClient` 빈에는 타임아웃이 없다. JSON 조회는 전용 RestClient를 쓰거나 타임아웃을 명시한 클라이언트가 필요하다.
  - 선례: `dartRestClient`(connect 3s / read 15s)

**캐시 선례와 Caffeine 계약**
- 캐시 선례는 `GlobalIndicatorCacheService`다.
  - LoadingCache로 같은 key 요청을 한 번의 로딩으로 합친다.
  - `EmptyAwareExpiry`로 빈 결과는 60s, 그 외는 12h TTL을 준다.
- Caffeine 공식 Javadoc/FAQ에서 확인한 계약:
  - `get(key, fn)`은 key별로 원자적이고, 함수는 key당 최대 한 번 실행된다.
  - 함수가 예외를 던지면 엔트리를 만들지 않는다. 즉 오류는 캐시되지 않는다.
  - null을 반환하면 저장하지 않는다.
  - 로드가 실패하면 같은 key의 후속 요청이 순차로 재시도한다. 공식 문서는 이를 negative caching으로 완화하라고 권고한다.

**오류 응답과 타임아웃**
- `GlobalExceptionHandler`의 외부 API 예외 그룹은 502 `EXTERNAL_API_ERROR`로 응답한다. 새 예외는 이 그룹에 등록해야 한다.
- 프론트 `API.request` 기본 타임아웃은 15초다. 최대 11개 날짜를 순차 조회하면 초과할 수 있다.
  - 선례: `previewCompanyReport`는 `timeoutMs: 60000`을 쓴다.
  - 서버 쪽에도 전체 조회 벽시계 상한이 필요하다(solution: parallel-external-fetch-resilience).
- 운영 보안 설정은 `anyRequest().authenticated()`다. 새 조회 API도 로그인이 필요하다.

**실행 환경 제약**
- 클라우드 세션의 네트워크 정책이 `www.koreaap.com`을 차단한다.
- 그래서 이 세션에서는 다음을 할 수 없다.
  - 응답 원문 확보(파서 fixture용)
  - 과거·휴일 날짜 실측
  - `bootRun` + curl 실검증
