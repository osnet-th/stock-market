## 요청 이해
주식은 연결 현금 자산(계좌)을 고를 수 있다. 연결한 현금 자산에 금융기관이 있으면 주식의 금융기관은 그 값을 따르고, 주식에서는 바꿀 수 없다.

## 문제 정의
- 주식을 키움 CMA에 연결해도 주식마다 금융기관을 한 번 더 입력해야 한다.
- 입력하지 않으면 금융기관별 합계에서 그 주식 평가액이 "미지정"으로 빠지고, 증권사 합계에는 CMA 잔액만 잡힌다.
- 연결한 현금 자산과 주식의 금융기관이 다르게 입력될 수 있다(예: 키움 CMA에 연결했는데 주식은 "미래에셋").

## 목표
- 연결 현금 자산에 금융기관이 있으면, 연결된 주식은 따로 입력하지 않아도 그 금융기관으로 보이고 합계에 잡힌다.
- 현금 자산의 금융기관을 바꾸면 연결된 주식도 함께 바뀐다.
- 연결 현금 자산에 금융기관이 있으면 주식 등록·수정 창에서 금융기관을 바꿀 수 없다.
- 연결하지 않은 주식과 다른 자산군은 지금처럼 자기 칸에 입력한다.

## 범위
- 주식의 적용 금융기관 판단 규칙
- 보유 자산 표의 금융기관 표시, 금융기관별 합계 카드
- 주식 등록·수정 창의 금융기관 칸 동작

## 제외 범위
- 다른 자산군(채권·펀드·금·암호화폐 등)의 입력 방식. 계좌를 연결하는 구조가 없다.
- 연결 현금 자산 구조(매수 금액 차감, 연결된 현금 자산 삭제 제한) 변경
- 금융기관 목록 관리, 계좌번호 저장(#136 제외 범위 유지)

## 현재 코드 확인 결과
- **저장:** `portfolio_item.institution`(VARCHAR(50) NULL) 하나를 모든 자산군이 같이 쓴다. 앞뒤 공백을 지우고 빈 값은 null로 저장한다(`PortfolioItem.java:261-268`).
  - 서버는 저장하고 응답에 담기만 한다. 챗봇·알림·스냅샷 등 다른 곳에서는 쓰지 않는다.
- **입력 칸:** 등록·수정 창은 자산군과 관계없이 같은 "금융기관" 칸 하나다. 선택 입력이고 이미 쓴 이름을 자동 완성으로 제안한다(`portfolio-add.html:398-408`, `portfolio-edit.html:308-317`, `portfolio.js:1309-1316`).
- **연결 현금 자산:** 주식 등록·수정 창에서 고른다(`portfolio-add.html:129-139`, `portfolio-edit.html:67-78`).
  - 연결하면 매수 금액을 현금 자산에서 뺀다(`PortfolioService.java:116-138`).
  - 연결 정보는 `CashStockLink`에 둔다. 주식 1건은 현금 자산 최대 1건, 현금 자산 1건은 주식 여러 건에 연결된다.
  - 연결된 현금 자산은 삭제할 수 없다(`validateCashDeletion`).
- **목록 응답:** 주식 항목에 `linkedCashItemId`가 담겨 온다(`PortfolioService.java:349-362`). 같은 목록에 현금 자산도 있어서 화면이 연결 현금 자산의 금융기관을 바로 찾을 수 있다(`getLinkedCashName`, `portfolio.js:1303-1307`과 같은 방식).
- **표시:** 보유 자산 표의 주식 행은 항목명, 자기 금융기관, "연결 · {현금 자산 이름}" 또는 "미연결" 배지를 보인다(`portfolio-holdings.html:289-295`).
- **합계:** `getInstitutionTotals`는 항목의 `institution`만 보고 묶고, 비어 있으면 "미지정"이다(`portfolio.js:868-894`). 아무 항목에도 금융기관이 없으면 입력 안내 문구를 보인다(`portfolio-holdings.html:128-130`).

## 후보 접근
- **A. 화면에서 적용 금융기관을 계산한다(저장 값은 그대로).**
  - 연결 현금 자산에 금융기관이 있으면 그 값을 쓰고, 없으면 주식 자기 값을 쓴다.
  - 표 표시, 합계 카드, 수정 창이 같은 함수를 쓴다.
  - 장점: DB·API 변경이 없다. 현금 자산의 금융기관을 바꾸면 바로 따라간다. #136의 합계도 화면에서 계산한다.
  - 단점: 응답의 `institution`은 주식 자기 값 그대로다. 나중에 서버에서 금융기관을 쓰면 같은 규칙을 서버에도 둬야 한다(지금은 서버 사용처 없음).
- **B. 서버가 응답에 적용 금융기관을 담는다.**
  - 장점: 규칙이 서버 한 곳에 있다.
  - 단점: API 계약이 바뀐다. 수정 창은 자기 값과 적용 값을 구분해야 해서 응답 필드가 하나 더 필요하다.
- **C. 저장할 때 연결 현금 자산의 금융기관을 주식에 복사한다.**
  - 장점: 읽는 쪽은 바뀌지 않는다.
  - 단점: 현금 자산의 금융기관을 바꾸면 연결된 주식을 모두 고쳐야 하고, 기존 데이터 이관이 필요하다. 값이 다시 어긋날 수 있다.

## 권장 접근
A를 권장한다. 금융기관을 쓰는 곳이 화면뿐이고, 현금 자산을 고치면 연결된 주식이 따로 저장하지 않아도 함께 바뀐다.

## 결정 사항 (요청에서 확정)
- 연결 현금 자산에 금융기관이 있으면 주식은 그 금융기관을 따른다.
- 이때 주식에서는 금융기관을 바꿀 수 없다. 등록·수정 창은 입력 칸 대신 "연결 계좌 기준: {금융기관}" 안내를 보인다. 연결하지 않았거나 연결 현금 자산에 금융기관이 없으면 지금처럼 입력 칸을 보인다.

## 태형님 확인 필요
1. **연결 현금 자산에 금융기관이 없을 때**
   - 권장: 주식 자기 값을 쓰고, 그것도 없으면 "미지정"이다.
   - 대안: 연결 계좌 기준만 쓰고 "미지정"으로 둔다.
2. **서버에서도 막을지**
   - 권장: 화면에서만 막는다. 연결 현금 자산을 따르는 동안 주식에 저장된 값은 표시와 합계에 쓰이지 않아, API로 다른 값을 보내도 보이는 금융기관은 바뀌지 않는다. API 동작은 그대로다.
   - 대안: 서버도 이 경우 요청의 금융기관을 저장하지 않는다. 연결 현금 자산을 조회해야 하고 API 동작이 바뀐다.
3. **이미 입력한 주식 자기 값**
   - 권장: 지우지 않는다. 연결 현금 자산의 금융기관을 따르는 동안은 쓰지 않고, 연결을 끊거나 현금 자산의 금융기관을 비우면 다시 쓴다. 데이터 이관은 없다.
   - 대안: 연결 현금 자산을 따르는 주식은 저장할 때 자기 값을 비운다.
4. **보유 자산 표 표시**
   - 권장: 항목명 옆에 적용 금융기관을 지금과 같은 모양으로 보인다. "연결 · {현금 자산 이름}" 배지는 그대로 둔다.
5. **진행 방식**
   - 권장: 이슈를 등록하고 세션 브랜치와 하네스 절차를 따른다.
   - 바뀌는 곳이 화면 계산뿐이라 새 Java 단위 테스트는 대상이 없다. 체크포인트에서 저장소 밖 브라우저 하네스(실제 partial·JS)로 확인하고, 전체 `./gradlew test`로 회귀를 본다.
