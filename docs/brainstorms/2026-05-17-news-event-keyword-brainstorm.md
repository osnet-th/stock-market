# 뉴스 기록 키워드 입력 브레인스토밍

> 원천 이슈: #46

## 문제 정의

뉴스 기록(`newsjournal`) 사건에는 WHAT/WHY/HOW 본문과 관련 기사 링크는 있으나,
사건을 대표하는 **키워드**를 별도로 기입할 수 없다. 사용자가 해시태그처럼 키워드를
여러 개 나열해 사건을 분류·회고할 수 있어야 한다.

## 요구사항 (이슈 #46)

- 뉴스 기록에 중요 키워드 입력 칸 추가
- 관련 기사 링크처럼 여러 개를 나열하는 형태
- 해시태그처럼 키워드만 나열
- 선택 입력 (0개 허용)

## 결정

- **저장 방식**: 별도 자식 테이블 `news_event_keyword` 신설. `NewsEventLink` 패턴을
  그대로 복제한다. (사용자 확정)
- **범위**: 키워드 입력·저장·표시까지. 키워드 클릭 시 타임라인 필터링은 이번 범위에서
  제외하고 별도 이슈로 남긴다. (사용자 확정)
- **키워드 모델**: 키워드는 단순 문자열 값이다. `title`/`url` 쌍을 갖는 링크와 달리
  별도 Command record(`NewsEventLinkCommand` 같은) 없이 `List<String>`을 직접 쓴다.
- **정규화**: 입력값은 앞쪽 `#`만 제거 후 trim. 그 외 원문 보존. 표시 시 UI에서 `#`
  prefix를 부여한다 (저장값에는 `#` 미포함).
- **상한**: 키워드당 50자, 사건당 최대 20개 (링크와 동일 상한).
- **갱신 정책**: 링크와 동일하게 replace-all (사건 수정 시 전체 삭제 후 재저장).
- **DB**: 본 프로젝트는 `ddl-auto: update`를 사용하므로 새 테이블은 자동 생성된다.
  마이그레이션 SQL 파일은 불필요 (신규 옵셔널 데이터, 백필 대상 없음).

## 영향 범위

- Entity 신규 1종(`NewsEventKeywordEntity`) + 도메인 모델 1종(`NewsEventKeyword`)
- 기존 공개 API의 request/response 스키마에 `keywords` 필드 추가
  (옵셔널 필드 추가 → 기존 클라이언트 하위호환)
- 프론트 뉴스 기록 모달 + 타임라인 카드
