## 요청 이해
금융기관을 글자로 입력하는 대신 정해진 목록에서 고르게 한다.

## 문제 정의
- 지금은 글자 입력칸에 자동 완성을 붙인 형태다. 미리 정한 목록이 없어 처음에는 제안이 비어 있고, 기관명을 직접 쳐야 한다.
- 같은 기관을 다르게 쓰면(예: 국민은행 / KB국민은행) 합계 카드에서 따로 묶인다. 자동 완성은 이를 줄일 뿐 막지 못한다.

## 목표
- 등록·수정 화면에서 금융기관을 목록에서 고른다.
- 목록에 없는 기관도 기록할 수 있다.
- 이미 입력한 값, 보유 자산 테이블, 금융기관별 합계 카드는 그대로 동작한다.

## 범위
권장안 기준이며 확인 후 확정한다.
- 프론트: 등록·수정 모달의 금융기관 칸을 선택 칸으로 바꾸고, 기관 목록과 선택값 ↔ 저장값 변환을 둔다.
- 백엔드·DB·API는 바꾸지 않는다. 저장값은 지금처럼 기관명 문자열이다.

## 제외 범위
- 사용자별·관리자 목록 관리 화면, 기관 코드 저장, 외부 API로 목록 받아오기
- 이미 입력한 값 자동 변환(예: 국민은행 → KB국민은행)
- 보유 자산 테이블·합계 카드 표시 방식 변경, 기관 유형별 합계
- 연금 "운용사" 칸

## 현재 코드 확인 결과
- **입력칸:** 등록·수정 모달 모두 글자 입력칸 + 자동 완성 목록(`datalist`)이다(`portfolio-add.html:383-393`, `portfolio-edit.html:293-303`). 최대 50자, 안내 문구는 "예: 국민은행, 키움증권, 업비트 (선택)"이다.
- **자동 완성 목록:** 보유 항목의 금융기관 값을 중복 없이 가나다순으로 모은다(`portfolio.js:1301` `getInstitutionNames`). 미리 정한 목록은 없다.
- **폼 값**
  - 등록 폼은 모달을 열 때 `{}` 또는 `{ region: 'DOMESTIC' }`로 초기화된다(`portfolio.js:1243`, `:1250`).
  - 수정 폼은 `institution: item.institution || ''`로 채운다(`:1973`).
  - 등록 7종·수정 7종 요청이 `institution: form.institution || null`을 보낸다(`:1371-1437`, `:2114-2181`).
- **서버:** 앞뒤 공백을 지우고 빈 값은 미지정(null), 50자 초과는 400이다(`PortfolioItem.updateInstitution`). 목록 검사는 없다.
- **표시·합계:** 보유 자산 테이블과 합계 카드는 저장된 문자열 그대로 보이고 묶는다(`portfolio.js:868` `getInstitutionTotals`, `portfolio-holdings.html:122-153`, `:243`, `:290`).
- **선택 칸 패턴:** 모달의 다른 선택 칸은 기본 `<select>`이고, 바뀌는 옵션은 `<template x-for>`로 그린다(예: 연결 현금 자산 `portfolio-add.html:132-136`).
- **운영:** #136은 2026-10-04 운영에 반영됐다. 그 뒤 입력한 값이 있을 수 있다.

## 후보 접근
- **A. 화면에 고정 목록을 두고 선택 칸으로 바꾼다(직접 입력 포함).**
  - 기관 목록을 `portfolio.js` 상수로 둔다. 선택 칸은 기관 유형별 묶음(`optgroup`)으로 보이고, 끝에 "직접 입력"을 둔다.
  - 장점: 서버·DB·API 변경이 없다. 이미 입력한 값과 합계가 그대로 동작한다.
  - 단점: 목록을 바꾸려면 코드를 고쳐 배포해야 한다.
- **B. 서버에 목록을 두고 조회 API로 내려준다(enum 또는 설정).**
  - 장점: 목록 원본이 서버 한 곳이고, 서버에서 값을 검사할 수 있다.
  - 단점: API와 서버 코드가 늘어난다. 직접 입력을 허용하면 서버 검사의 의미가 약하다.
- **C. 사용자가 자기 기관 목록을 관리한다(관리 화면 + 테이블).**
  - 장점: 원하는 이름으로 목록을 꾸린다.
  - 단점: Entity·테이블·API·관리 화면이 새로 필요하다. #136에서 제외한 "금융기관 목록 관리"다.
- **D. 입력칸은 두고 자동 완성에 고정 목록을 미리 채운다.**
  - 장점: 변경이 가장 작다.
  - 단점: 여전히 글자 입력칸이라 고르는 칸이 아니다. 요청과 다르다.

## 권장 접근
A를 권장한다.
- 선택 칸 순서: "선택 안 함" → 유형별 기관 묶음 → "내가 입력한 기관"(목록에 없는 기존 값, 있을 때만) → "직접 입력"
- "직접 입력"을 고르면 아래에 글자 입력칸(최대 50자)이 열린다. 한 번 입력한 이름은 다음부터 "내가 입력한 기관"에서 고른다. 그래서 자동 완성 목록(`datalist`)은 없앤다.
- 수정 모달은 저장된 값을 같은 이름의 옵션으로 고른 상태로 연다. 목록에 없는 값은 "내가 입력한 기관" 묶음에 있다.
- 저장값, 서버, 보유 자산 테이블, 합계 카드는 바꾸지 않는다.

## 태형님 확인 필요
1. **목록을 두는 곳**
   - 권장: 화면 코드의 고정 목록(접근 A). 서버·DB·API는 그대로다.
   - 대안: 서버 목록 + 조회 API(B), 사용자 목록 관리(C)
2. **목록에 없는 기관**
   - 권장: "직접 입력"을 두고, 한 번 입력한 이름은 다음부터 "내가 입력한 기관"에서 고른다.
   - 대안: 목록에 있는 기관만 고를 수 있다(직접 입력 없음).
3. **목록 범위와 묶음**
   - 권장: 개인이 주로 쓰는 기관 위주로 유형별 묶음을 둔다.
     - 은행: 시중·지방·인터넷·특수은행
     - 증권: 주요 증권사
     - 가상자산 거래소: 원화 거래소
     - 보험: 연금저축보험 같은 상품을 위한 주요 생명·손해보험사
     - 기타: 우체국, 새마을금고, 신협 등
   - 기관 이름과 출처(금융감독원·은행연합회·금융정보분석원 공개 목록)는 plan에서 확정해 확인받는다.
   - 대안: 은행·증권만 둔다.
4. **이름 표기**
   - 권장: 공식 표기를 쓴다(예: KB국민은행, NH농협은행).
   - 대안: 줄인 이름을 쓴다(예: 국민은행, 농협은행).
5. **이미 입력한 값**
   - 권장: 그대로 둔다. 목록과 이름이 같으면 그 기관으로, 다르면 "내가 입력한 기관"으로 보인다. 목록 기관으로 바꾸려면 수정 화면에서 다시 고른다.
   - 대안: 알려진 별칭(예: 국민은행 → KB국민은행)을 한 번에 바꾸는 SQL을 둔다. 기존 데이터를 바꾸므로 DB 리뷰가 필요하다.
6. **자산군별 목록**
   - 권장: 모든 자산군에 같은 목록을 보인다.
   - 대안: 자산군에 맞는 묶음을 위로 올린다(예: 주식은 증권 먼저).
7. **진행 방식**
   - 권장: 세션 브랜치와 하네스 절차를 따른다.
   - Java 코드가 바뀌지 않으므로 단위 테스트는 쓰지 않는다. 저장소 밖 브라우저 하네스로 선택 칸, 직접 입력, 수정 모달 값 복원, 요청 본문을 확인한다.
