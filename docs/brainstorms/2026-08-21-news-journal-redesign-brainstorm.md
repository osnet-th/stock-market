## 문제 정의

태형님이 목업 HTML(업로드 `b18ca2f9-*.html`)을 제시하며 "현재 뉴스기록 화면을 이 html 로 변경하고
부족한 기능은 백엔드 코드 추가 또는 수정해서 맞춰줘"라고 요청했다.

현재 뉴스 기록(`partials/news-journal.html` 302줄 + `components/news-journal.js` 335줄)은:
1. 세로 타임라인 카드 목록 (WHAT/WHY/HOW 전문 노출)
2. 주제 분류 탭 + 시장영향/기간 필터 바 + "필터 적용" 버튼
3. 생성/수정은 **모달**
4. 서버 페이지네이션 (이전/다음 버튼, 20건)

목업은 이걸 **검색·키워드 중심 마스터-디테일 화면**으로 재구성한다.

색 토큰·폰트는 #110/#114 와 동일 계열(`--dc-*`, IBM Plex)이라 기존 `custom.css` 토큰을 재사용한다.

### 핵심 동작 (목업 로직에서 확인)

- **모달 폐지** — 보기/수정/새 기록 모두 우측 pane 인라인. 빈 선택 상태 문구
  "모달 대신 이 자리에서 바로 읽고 수정합니다. 작성 중 화면을 벗어나도 초안은 남습니다."
- **초안 보관(stash)** — 새 기록 작성 중 닫으면(닫기/ESC) 내용이 남아 있는 경우 초안으로 보관,
  헤더에 "작성 중 초안 · {미리보기} — 이어쓰기" 칩 노출. 저장하면 초안 소멸.
  기존 기록 수정 중 닫기는 폐기(목업 `hasContent` 가 `!d.id` 조건).
- **통합 검색** — 제목 + WHAT/WHY/HOW 본문 + 키워드 + 분류명까지 한 입력으로 검색.
- **키워드 필터** — 칩 클릭 토글, 다중 선택은 **AND** ("A + B 모두 포함"). 칩엔 기록 수 뱃지.
- **키워드 패널** — "+N개 더" 팝오버: 추천 탭(선택한 것과 함께 쓰인 / 자주 쓰는 / 최근 기록에 쓴)
  + 가나다 탭(초성 그룹). 검색 입력은 **초성 검색**(ㅂㄷㅊ) 지원.
- **키워드 관계도** — 뷰 토글. 원 크기=기록 수, 선 굵기=동시 등장 횟수, hover/선택 하이라이트,
  하단 "가장 자주 겹치는 짝" 칩 → 클릭 시 해당 2개 키워드로 목록 필터.
- **그룹 목록** — 월별/분류별 그룹, sticky 그룹 헤더, 행 클릭 → 디테일. 페이지네이션 UI 없음.
- **시장영향 세그먼트** — 전체/호재/악재/중립 각각 건수 뱃지 (전체 기준, 필터와 무관).
- **분류 드롭다운** — 탭 대신 검색 가능한 드롭다운 + 건수, "저장하면 새 분류 자동 추가" 안내.
- **기간 지정** — 토글 버튼 → from~to date 입력 노출.
- **좁은 화면** — 목록/디테일 단일 pane 전환 + "‹ 목록으로 (N건)" 백 버튼.
- **편집 폼** — 제목*/발생 일자*/시장영향*(3버튼)/주제 분류*(칩+새 분류 Enter),
  WHAT/WHY/HOW(힌트·글자수·placeholder), 관련 기사(제목 선택+URL, https 형식 아니면 경고 보더),
  키워드(칩 삭제+Enter 추가), dirty 시 "작성 내용은 자동 보관됩니다" 안내.

## 현재와의 차이 (gap)

| 항목 | 현재 | 목업 | 백엔드 영향 |
|---|---|---|---|
| 레이아웃 | 타임라인 전문 노출 | 마스터-디테일 + 미리보기 | 없음 (list 응답에 전문 포함) |
| 편집 | 모달 | 인라인 pane + 초안 보관 | 없음 (초안은 localStorage) |
| 검색 | 없음 | 제목+본문+키워드+분류 통합 검색 | **필요: `q` 파라미터** |
| 키워드 필터 | 없음 | 다중 AND 필터 | **필요: `keywords` 파라미터** |
| 임팩트/분류 건수 | 없음 | 세그먼트·드롭다운 뱃지 | **필요: 통계 API** |
| 키워드 칩/패널/관계도 | 없음 | 빈도·동시등장 기반 | **필요: 사건별 키워드 통계** |
| 페이지네이션 | 이전/다음 | 없음 (전량 스크롤) | 기존 페이징 재사용(더 불러오기) |
| 관련 기록 | 없음 | 같은 분류 3건 | 없음 (로드분에서 계산) |

## 결정 사항

1. **'약재' → '악재'** — 목업 상수의 '약재'는 오타로 판단(투자 용어는 악재).
   기존 `EventImpact.BAD`='악재' 표기 유지. Enum 변경 없음.
2. **앱 셸 유지** — 목업의 자체 사이드바/계정 박스는 목업용 셸. 기존 `_sidebar`/`_header` 유지,
   partial 콘텐츠 영역만 교체.
3. **초안 보관은 localStorage** — 단일 초안(목업과 동일), 사용자별 키(`newsJournalDraft:{userId}`).
   서버 저장은 과설계로 판단. 탭/브라우저 재시작에도 유지되어 목업 문구("닫아도 사라지지 않습니다")
   충족.
4. **목록은 "더 불러오기" 증분 로드** — 목업은 페이지네이션이 없으나 무제한 전량 로드는 피한다.
   100건 단위 append, 남은 건수 표시. 그룹 헤더 건수는 로드분 기준.
5. **검색·키워드 필터는 서버사이드** — `NewsEventListFilter` 에 `query`(제목/WHAT/WHY/HOW/키워드/
   분류명 LIKE) + `keywords`(전부 포함 AND) 추가. 증분 로드와 정합 유지 목적.
6. **화면 통계는 신규 `GET /api/news-journal/stats`** — 임팩트별 건수 + 분류별 건수 +
   **사건별 키워드 목록**(eventId·occurredDate·keywords). 빈도/동시등장/추천/관계도는
   이 데이터로 프론트 계산 (목업 로직과 동일 산식 유지, 다중 선택 AND 연관 계산에 사건 단위 필요).
7. **관계도는 React 미도입** — Alpine 상태 + SVG 엣지(x-html) + 절대배치 노드 버튼으로 구현.
8. **삭제 confirm 유지** — 목업은 즉시 삭제지만 복구 수단이 없어 기존 확인 창 유지.
9. **링크 제목은 선택 입력** — 목업대로 "기사 제목 (선택)". 백엔드 `NotBlank` 는 유지하고
   빈 제목은 URL 로 대체 저장(목업 표시 로직 `l.title || l.url` 과 동일 결과).
10. **발생 일자 미래 금지 유지** — 도메인 규칙(`NewsEvent.create`) 존재. 목업엔 제한이 없지만
    기존 규칙 우선, date input `max=today` 유지.
11. **Entity/스키마 변경 없음** — 마이그레이션 불필요.

## 신규/변경 API 스케치

```
GET /api/news-journal/events?impact&categoryId&from&to&page&size&q&keywords=a&keywords=b
  → 기존 응답 동일 (items/totalCount/page/size)

GET /api/news-journal/stats
  → {
      totalCount,
      impactCounts: { GOOD, BAD, NEUTRAL },        // 사용자 전체 기준
      categories: [{ id, name, count }],           // 이름순, 0건 포함
      keywordEvents: [{ eventId, occurredDate, keywords: [] }]  // 키워드 보유 사건만
    }
```

## 리스크

- 화면 전면 교체라 기존 조작 습관(타임라인 전문 노출)이 사라짐 — 목업 요청 자체가 근거.
- `q` LIKE 검색은 인덱스를 타지 않음 — 개인 기록 규모(수백~수천)에서 문제 없음. ES 전환은 범위 밖.
- stats 의 keywordEvents 는 사건 수에 비례 — 동일 규모 전제에서 수십 KB 이내.
