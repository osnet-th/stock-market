# Multi-Year Financial Timeline (몇 년치 재무정보 한 화면) - Brainstorm

**Date:** 2026-07-05
**Status:** Decided

## What We're Building

한 종목(단일 회사)의 여러 해치 재무정보를 **한 화면에서** 보는 딥 시계열 화면.
상단은 요약 추세(재무계정 + 핵심 비율 + 발행 주식수 + **잉여현금흐름(FCF)**), 하단은 **전체 재무제표 세부 계정**(재무상태표/손익계산서/현금흐름표 등)과 **재무지표 전체(4분류)**의 연도별 시계열 표.

- **과거 연도**: 사업보고서(연간 확정치) 기준
- **올해**: 아직 사업보고서가 없으므로 그 해 나온 **최신 정기보고서(분기/반기)** 기준 — DART 공시검색(`list.json`)으로 실제 존재하는 최신 보고서를 탐지
- 혼합 주기 조립은 **백엔드가 자동 처리**. 프론트는 기간(몇 년)만 요청

### API 스케치

```
GET /api/stocks/{stockCode}/financial/timeline?years=5&items=accounts,indices,shares,details&fsDiv=CFS
```

응답의 각 연도 항목에 `연도 · 기준보고서 · 진행중 여부(partial)`가 붙는다.
`details`는 전체 재무제표 세부 계정 시계열, `fsDiv`는 연결(CFS)/개별(OFS) 선택.

### 변경 범위

1. **백엔드**: DART 공시검색(`list.json`) 클라이언트 추가(올해 최신 정기보고서 탐지용), timeline 조립 서비스 + 신규 조회 API — 요약(재무계정·비율·주식수)과 세부(전체 재무제표) 모두 연도 루프로 수집·병합
2. **프론트엔드**: 한 화면 구성 — 상단 요약 추세 차트(+주식수 별도 차트), 하단 재무제표 종류별(BS/IS/CF 등) 접이식 세부 계정 시계열 표. 올해 칸은 점선/배지("N분기·진행중")로 구분

### 변경하지 않는 것

- 기존 단건 조회 화면/API (`/financial/accounts` 등) — 그대로 유지
- 공시 원문 파일 다운로드/파싱 (`document.xml`) — 하지 않음. 원문은 DART 뷰어 링크로만
- 재무 데이터 소스 — 기존과 동일한 DART 정기보고서 API(`fnltt*` 등). 새 데이터가 생기는 게 아니라 진입점/조회 방식 개선

## Why This Approach

- **주기 혼합 문제 해결**: "과거는 사업보고서, 올해는 분기/반기"를 사용자가 화면에서 직접 고르게 하면 UX가 복잡해진다. 백엔드가 조립하면 프론트는 기간만 넘기면 된다.
- **`list.json`으로 정확한 탐지**: 올해 어떤 정기보고서까지 나왔는지(1분기? 반기?)를 월 기준 추정 대신 실제 공시 목록으로 확인 → 정확.
- **기존 인프라 재활용**: 종목코드→고유번호 변환(`DartCorpCodeCache`), 재무 조회(`StockFinancialService`), 주식총수(`stockTotqySttus`)가 모두 구현돼 있어 timeline은 "연도 루프 + 병합" 로직만 추가하면 된다.
- **착시 방지**: 연간(12개월) 옆에 분기 누적(3개월)을 그대로 놓으면 급감으로 보인다 → 올해 칸은 점선/배지로 "진행중"임을 명시.

## Key Decisions

### 대화에서 확인한 질문과 답

| 질문 | 확인 결과 |
|------|----------|
| 종목 선택 시 공시 리스트 조회 가능? | 가능. DART `list.json` (공시검색). `rcept_no`로 뷰어 링크(`dart.fss.or.kr/dsaf001/main.do?rcpNo=...`) 연결 |
| 공시 원문 파일 다운로드 가능? | 가능하나 `document.xml` ZIP 안은 PDF가 아닌 DART 고유 XML. **뷰어 링크만 유지하기로 결정** |
| 리스트에 모든 보고서가 나오나? | 지정 기간 내 전 유형이 접수일 최신순으로. 기간 미지정 시 최근 3개월만, 페이지당 최대 100건 |
| 공시 유형 종류? | `pblntf_ty` A~J 10종 (A정기, B주요사항, C발행, D지분, E기타, F외부감사, G펀드, H자산유동화, I거래소, J공정위) + 상세유형 |
| 유형 다중선택 가능? | UI는 다중선택 가능. API는 1콜 1유형이므로 백엔드가 유형별 호출 후 접수일 기준 병합 (검증 필요) |
| 공시 선택 → 바로 재무제표? | **정기보고서만 가능** (`report_nm`의 `(YYYY.MM)` → `year+reportCode` 매핑). 그 외 유형은 재무 데이터가 없어 뷰어 링크만 |
| 기존 재무 기능의 키 기준? | 소송(`lwstLg`, 기간 기준) 제외 전부 `year+reportCode` (정기보고서 기준) |
| 발행 주식수 포함 가능? | 가능. `stockTotqySttus`(주식총수)가 이미 구현돼 있고 같은 `year+reportCode` 키 → timeline에 행 추가만 |

### 사용자 선택 사항

| 결정 사항 | 선택 | 이유 |
|----------|------|------|
| 표현 방식 | 표 + 차트 둘 다 | 숫자 정밀 비교(표) + 추세 파악(차트) |
| 데이터 범위 | 재무계정 + 주요 비율 (+ 발행 주식수) | 시작점으로 적당한 범위. 주식수는 이후 추가 요청 |
| 기간 단위 | 과거 = 사업보고서, 올해 = 최신 분기/반기 | 올해는 사업보고서가 아직 없음. 백엔드가 자동 조립 |
| 원문 접근 | 뷰어 링크만 (다운로드/파싱 없음) | 유지보수 0, 정정공시·첨부 자동 처리, PDF는 뷰어에서 가능 |
| 올해 진행중 값 처리 | 있는 그대로 + "진행중" 라벨 (점선/배지) | 연환산 추정은 오해 소지로 제외. 동기 대비(YTD) 토글은 추후 보조 옵션 |
| 주식수 차트 표시 | 금액 차트와 분리한 **별도 차트** | 주(株) 단위와 금액(조원) 단위는 스케일이 달라 같은 축 불가 |
| 주식수 주식 종류 | **보통주/우선주를 각각 시리즈로** 구분 표시 | 주식총수 API가 보통주/우선주를 각각 행으로 제공 → 그대로 활용 |
| 시계열 깊이 | 요약뿐 아니라 **전체 재무제표 세부 계정까지 시계열** (B안) | 주 용도가 단일 회사 깊이 보기. 한 화면에서 전체 추세와 세부 정보를 한번에 보고 싶다는 요구. 단일 회사는 연도 간 계정명이 안정적이고 `account_id`(IFRS 표준 ID)로 매칭 가능 |
| 화면 구성 | **상단 요약 추세(차트) + 하단 세부 계정 표**(재무제표 종류별 접이식 섹션) | 세부 계정은 연도당 수백 행 → 섹션 접기로 한 화면에 감당 |
| 개별/연결 | 연결(CFS) 기본 + 개별(OFS) 토글 (기본값 제안) | 상장사 대표 재무제표는 연결. 전체 재무제표 API가 fs_div를 요구하므로 토글 필요 |
| 잉여현금흐름(FCF) | 파생 지표로 시계열에 포함. 정의: **영업활동현금흐름 − 유형자산 취득 − 무형자산 취득** | DART가 직접 제공하지 않아 현금흐름표에서 조합. 이미 확보하는 전체 재무제표 데이터 기반이라 추가 호출 없음. 보수적 정의 채택(R&D 자산화 기업도 왜곡 없음) |
| 재무지표 표시 | **핵심 지표(영업이익률·ROE·부채비율 등 2~3개)는 상단 추세 차트**, 나머지 포함 **4분류(수익성·안정성·성장성·활동성) 전체는 하단 접이식 연도별 표** | 비율은 시계열일 때 가치가 가장 큼. 전부 차트에 올리면 노이즈 → 큐레이션 + 전체 표 병행. 차트에 올릴 핵심 지표 목록은 플랜에서 확정 |

### 파생 아이디어 (범위 외, 추후 검토)

- EPS(주당순이익 = 순이익 ÷ 발행주식수) 파생 항목
- 주식수 증감 표시 (유상증자·자사주 소각에 따른 희석 파악)
- 동기 대비(YTD) 비교 토글 (올해 1분기 vs 작년 1분기)

## Technical Notes

### 기존 인프라 재활용 가능한 부분

- `DartCorpCodeCache`: 종목코드 → DART 고유번호 변환 (24h 캐시)
- `DartApiClient` + `StockFinancialService`: 재무계정(`fnlttSinglAcnt`), 재무지표(`fnlttSinglIndx`), 주식총수(`stockTotqySttus`), 전체 재무제표(`fnlttSinglAcntAll`, `fetchSingleFullFinancial`) 조회 전부 구현됨
- `ReportCode` enum: `11011` 사업 / `11012` 반기 / `11013` 1분기 / `11014` 3분기

### 추가 구현 필요한 부분

- `DartApiClient.fetchDisclosureList(...)` — `list.json` 호출 (corp_code, bgn_de/end_de, pblntf_ty, page_no/page_count)
- 공시검색 응답 DTO — 기존 `DartApiResponse`는 `status/message/list`만 있어 `total_count/total_page/page_no` 페이징 필드 확장 필요
- timeline 조립 서비스: 과거 N년 사업보고서 루프 + 올해 최신 정기보고서 탐지·조회 + 병합
- timeline 조회 컨트롤러 + 프론트 화면(비교 표 + Chart.js 추세 차트, 진행중 점선/배지)
- 주식수 별도 차트: 보통주/우선주 2개 시리즈, 금액 차트 아래 배치. timeline 응답의 주식수 항목은 주식 종류(`category`/`se`)별로 분리해 내려줌 (우선주 미발행 종목은 보통주 시리즈만 표시)
- 세부 계정 시계열: 연도별 전체 재무제표를 `account_id` 기준으로 매칭해 "계정 × 연도" 매트릭스로 병합. `account_id`가 `-표준계정코드 미사용-`인 계정은 `계정명 + sj_div` 매칭으로 폴백
- `DartSinglAcntAllItem`에 전전기(`bfefrmtrm_nm`/`bfefrmtrm_amount`) 필드 매핑 추가 (현재 당기/전기만 매핑됨)
- FCF 파생 계산: 연도별 현금흐름표에서 영업활동현금흐름·유형자산 취득·무형자산 취득 3개 계정 추출 → `영업CF − |유형 취득| − |무형 취득|`. 취득액은 현금흐름표상 음수(유출)로 오므로 부호 처리 필요. 백엔드에서 계산해 요약 추세 항목으로 내려줌
- 프론트 세부 계정 표: 재무제표 종류별(BS/IS/CIS/CF/SCE) 접이식 섹션, 기본은 손익계산서만 펼침. 행 수가 많아 렌더링 부담 시 섹션 단위 지연 렌더링 고려
- 재무지표 시계열: `fnlttSinglIndx`를 4분류 × 연도 루프로 수집 → "지표 × 연도" 표. 하단에 접이식 "재무지표" 섹션으로 배치(분류별 그룹핑)

### 주의 사항

- `list.json`은 기간 미지정 시 최근 3개월만 반환 → 탐지 시 올해 1/1~오늘로 명시
- `list.json` 응답 행에는 유형코드가 없음(보고서명·접수번호·제출인·접수일·비고만) → 유형 필터는 요청 파라미터로만. **"1콜 1유형" 및 응답 필드 구성은 구현 전 실제 호출로 검증 필요**
- 사업보고서의 `fnlttSinglAcnt`는 당기/전기/전전기 3期를 한 번에 반환 → 호출 수 최적화 여지 (단, 분기/반기 응답에는 전전기(`bfefrmtrm`) 키 자체가 없음 — `docs/solutions` 아닌 세션 메모리에서 확인된 사실)
- 올해 최신 보고서의 값은 누적(YTD) 기준 → 연간 확정치와 직접 비교 불가함을 UI에 명시
- 회사가 연도 중 계정 구성/명칭을 바꾸면 일부 세부 계정은 특정 연도에 값이 없을 수 있음 → 빈 칸 허용 (0으로 채우지 않음)
- 현금흐름표 세부 계정은 표준계정코드 미사용(`-표준계정코드 미사용-`)이 잦음 → FCF용 유형/무형자산 취득 계정은 계정명 매칭 의존 가능성 높음. **구현 전 실제 응답으로 계정명·ID 검증 필요**. 매칭 실패 연도는 FCF도 빈 칸 처리
- 세부 계정 시계열은 회사 XBRL 원본 기반이라 **다른 회사와의 비교 용도로는 부적합** — 단일 회사 전용 화면임을 전제
- 재무지표 중 **성장성 지표(증가율류)는 진행중 연도 해석이 애매** (기간 비교 기반) → 올해 칸은 빈 칸 또는 각주 처리
- 재무지표 호출량: 분류당 1콜 × 4분류 × N년 (5년 기준 20콜) → 병렬 호출 + 결과 캐싱 고려. 비율은 시점값/동기간 비율이라 진행중 착시 문제가 절대값보다 덜함 (부채비율·유동비율은 시점값이라 분기도 연간과 직접 비교 가능)
