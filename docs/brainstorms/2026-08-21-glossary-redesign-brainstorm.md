## 문제 정의

태형님이 목업 HTML(업로드 `4b044daa-*.html`)을 제시하며 "이거 대로 용어 사전에 대한 화면
변경해주고 부족한 부분은 백엔드 코드 수정해서 보강해줘"라고 요청했다.

현재 용어 사전(`partials/glossary.html` 282줄 + `components/glossary.js` 334줄, 이슈 #43)은:
1. 카테고리 사이드바 + 카드 목록 (설명 전문 노출, 페이지네이션 20건)
2. 용어명/설명 **분리 검색** 입력 2개 + 정렬 select(최신/오래된/가나다)
3. 생성/수정은 **slideover 모달**, 필드는 용어명+설명+카테고리 3개뿐
4. 서버 사이드 검색/필터/정렬/페이지네이션

목업은 이걸 **구조화 학습 노트형 마스터-디테일 화면**으로 재구성한다.

## 목업 구조 (추출 결과)

번들 HTML(디자인 캔버스 `x-dc` 템플릿). 템플릿 본문 35KB + 상태 로직 스크립트를 추출해 대조했다.
색 토큰·폰트는 #114/#117 와 동일 계열(`--dc-*`, IBM Plex)이라 기존 `custom.css` 토큰을 재사용한다.

### 목업 데이터 모델 (용어 1건)

| 목업 키 | 의미 | 현재 백엔드 | 판단 |
|---|---|---|---|
| name | 용어명 | name ✅ | 유지 |
| abbr | 약어 · 영문 | 없음 | **신설** abbreviation |
| cat | 카테고리 | categoryId ✅ | 유지 (목업은 문자열, 실제는 ID 참조) |
| date | 등록일 | createdAt ✅ | 유지 |
| one | 한 줄 정의 | 없음 | **신설** oneLine |
| body | 풀이 | definition ≈ | **definition 재해석** (아래) |
| scale | 기준 · 읽는 법 | 없음 | **신설** scaleNote |
| example | 예시 | 없음 | **신설** example |
| takeaway | 투자 관점 | 없음 | **신설** takeaway |
| related | 함께 볼 용어 id[] | 없음 | **신설** relatedTermIds |

### 목업 동작 요약

- 통합 검색: name+abbr+one+body+scale+example+takeaway 를 한 입력으로 검색, 이름은 초성 매칭 병행
- 정렬 2종: 가나다(초성 그룹) / 최신(월별 그룹) — sticky 그룹 헤더 + 그룹별 건수
- 카테고리 칩: 전체 + 카테고리별 건수, 선택 시 다크(#14161a) 반전
- 목록 행: 미작성 배지 `N/4 작성`, 선택 행 흰 배경 + 파란 좌보더
- 디테일: 섹션 4종 컬러 카드(파랑/초록/앰버/빨강), 줄 단위 렌더 + `-`/`•` 서브불릿 들여쓰기
- 채움 nudge: 비어 있는 섹션 나열 + [채우기] → 편집 진입
- 초안: 새 용어 편집을 닫으면(닫기/Escape) 내용이 보관되고 헤더 칩으로 이어쓰기. 수정 편집은 보관 안 함(`hasContent`가 `!d.id` 요구)
- 저장: 검증 없이 저장(목업). 빈 필수 필드는 빨간 테두리 힌트만

## 자율 결정 (태형님 부재 중 판단 — 푸시 후 검토 요청)

1. **앱 셸 유지**: 목업의 자체 사이드바("Stock Market" 내비, 루뻥뻥/로그아웃)는 앱 셸의 목업 표현.
   partial 은 기존 헤더/사이드바 셸 안의 콘텐츠 영역만 목업대로 구현한다 (#117 선례와 동일 판단).
2. **definition = '풀이' 재해석**: 스키마 권위가 Entity + `ddl-auto: update` 라 컬럼 rename 은
   기존 데이터를 고아로 만든다. `definition` 컬럼/필드명은 유지하되 화면 의미를 '풀이'로 쓴다.
   기존 설명 텍스트가 그대로 풀이 섹션에 나타난다 — 데이터 마이그레이션 불필요.
3. **함께 볼 용어 = @ElementCollection ID 리스트**: Entity 연관관계 금지 규칙(ID 참조만)에 맞게
   `glossary_term_related(term_id, related_term_id)` 컬렉션 테이블. 저장 시 소유권 검증
   (본인 용어 id 만 허용), 자기 참조 제거, 중복 제거, 상한 20. 용어 삭제 시 양방향 정리
   (JPQL 벌크 DELETE 는 컬렉션 행을 안 지우므로 native 정리 쿼리 별도).
   끊긴 참조는 목업과 동일하게 렌더 시 필터(방어).
4. **검색/초성/그룹/건수 = 클라이언트 사이드**: 개인 사전 규모(수백 건 이하)라 전량 로드
   (기존 list API, 200건/페이지 루프) 후 목업 로직 그대로 클라이언트에서 수행.
   서버 `q`/`definitionQ` 파라미터는 하위호환 유지(신 UI 미사용, API 계약 불변).
5. **초안 = localStorage**: 목업의 in-memory 보관("닫아도 사라지지 않습니다")을 새로고침에도
   살아남게 localStorage 로 구현. 목업 로직대로 **새 용어만** 보관, 수정 편집은 보관 안 함.
6. **카테고리 관리 보존**: 목업에 카테고리 이름 변경/삭제 UI 가 없지만 기존 기능(R6 삭제 영향
   미리보기 포함)을 제거하지 않는다. 칩 행 끝 '관리' 팝오버(#117 nj-pop 스타일)로 이동.
7. **정렬 2종 축소**: 목업대로 가나다/최신 2종만 노출. backend enum(REGISTERED_ASC 포함)은 유지.
8. **한 줄 정의 소프트 필수**: 목업은 `*` 표기 + 빨간 테두리 힌트만 있고 저장은 막지 않는다.
   레거시 용어(one 없음) 호환 위해 백엔드 nullable, 프론트도 저장 허용 + 목록 fallback
   ('한 줄 정의가 비어 있습니다'). 용어명만 하드 필수(기존과 동일).
9. **삭제 confirm 유지**: 목업은 즉시 삭제지만 복구 불가 데이터라 기존 confirm 유지.
10. **좁은 화면 임계 1280px**: 목업 1080px + 앱 사이드바(224px) 보정 (#117 실측 선례).
11. **페이지네이션 UI 제거**: 전량 로드로 대체. 스크롤 목록이 페이지 이동을 대신한다.
12. **채움 필요 카운트**: 헤더 '등록 N개 · 채움 필요 N개'는 4개 섹션(풀이/기준/예시/투자 관점)
    중 하나라도 빈 용어 수. 목업 filled() 로직 그대로.
