## 이슈 상세 기반 이해
만기가 지난 적금·예금에서 생기는 두 가지 어색한 동작을 정리한다.
- 납입 알림: 만기일 당일부터는 납입일 당일·미납 알림 대상에서 뺀다.
- 자동 납입: 만기가 지난 항목을 "납입일에 자동 납입"으로 저장할 때의 처리(막기 또는 안내)를 정하고, 설명 줄의 "자동 납입" 표시를 정리한다.
- 만기 전 항목의 알림과 자동 납입은 지금과 같아야 한다. 만기 해지·재예치 처리는 범위 밖이다.

## 문제 정의
- 납입 알림(당일·미납) 판정은 만기일을 보지 않는다. 만기가 지난 적금·예금도 납입일 설정이 남아 있으면 매달 알림 팝업, 설명 줄 "⚠ 미납", 표의 "미납" 배지, 납입 창의 "이번 달 납입이 필요합니다"가 뜬다. #138 이전부터 있던 동작이다.
- #138의 자동 납입은 만기일 당일부터 기록하지 않는다. 그런데 만기가 지난 항목도 자동 납입으로 저장되고 설명 줄에 "자동 납입"이 계속 보여, "자동 납입"과 미납 알림이 함께 보인다.

## 목표
- 만기가 지난 현금성 항목에는 당일·미납 알림과 미납 표시가 나오지 않는다.
- 만기가 지난 항목의 자동 납입 저장·표시가 정한 정책대로 동작한다.
- 만기 전 항목, 만기일이 없는 항목(CMA 등), 펀드·연금은 지금과 같다.

## 범위
권장안 기준이며, 태형님 확인 결과에 따라 확정한다.
- 백엔드: 현금성 상세의 만기 판단(도메인), 당일·미납 판정에서 만기된 현금성 항목 제외
- 프론트: 등록·수정 모달의 만기 지난 자동 납입 안내, 설명 줄의 "자동 납입" 표시 조건

## 제외 범위

- 펀드·연금(만기일이 없다), 납입 이력 구조, 자동 납입 배치 규칙(#138에서 이미 만기일부터 건너뛴다)

## 현재 코드 확인 결과
- **판정 위치:** `PortfolioService.getItems`가 현금성·펀드 항목의 `depositOverdue`·`depositDueToday`를 계산한다(`PortfolioService.java:393-396`). 기준일은 KST다(`:384`).
  - 두 판정 함수는 납입일(`resolveDepositDay`, `:1279-1290`)과 이번 달 기록만 본다(`:1246-1277`). 시작일·만기일은 보지 않는다.
  - 두 판정 함수의 기존 단위 테스트는 없다.
- **판정 결과 사용처(화면만):** 리마인더 팝업 대상(`portfolio.js:2282`), 설명 줄 "⚠ 미납"(`portfolio.js:1114`, `:1125`, `:1137`), 보유 자산 표 "미납" 배지(`portfolio-holdings.html:245`, `:296`), 납입 창 안내(`portfolio-deposit-financial.html:16`), 리마인더 목록 배지(`:164-165`). 메일·챗봇 등 서버의 다른 곳에서는 쓰지 않는다.
- **자동 납입:**
  - `CashDetail.isAutoDepositDueOn`은 만기일 당일부터 false다(`CashDetail.java:95-97`).
  - `validateDepositMode`는 만기를 보지 않는다(`:69-79`).
  - 설명 줄 "자동 납입"은 처리 방식만 본다(`portfolio.js:1133`).
  - 등록·수정 모달 안내는 "만기일부터는 건너뜁니다"를 이미 알린다(`portfolio-add.html:338`, `portfolio-edit.html:277`).
- **만기 표시 관례:** 보유 자산 표의 "현재가·만기" 열은 브라우저 현지 날짜로 D-day를 보이고, 만기일 다음 날부터 "만기 경과"를 보인다(`portfolio.js:934-950`, `getDaysUntil` `:896-903`). 홈의 만기 임박 알림은 D-0\~D-120만 다룬다(`home.js:442-475`).
- **만기일 없는 항목:** CMA는 만기일을 저장하지 않는다(`portfolio.js:1434`, `:2181`). 예금·적금도 만기일을 비워 둘 수 있다. 펀드 상세에는 만기일이 없다(`FundDetail.java:10-13`).

## 후보 접근

### 1. 알림 제외 (작업 내용 1)
- **A. 서버 판정에서 제외 (권장)**
  - 현금성 상세에 만기 판단(`isMaturedOn(date)`: 만기일이 있고 date가 만기일 당일 이후)을 두고, 당일·미납 판정이 만기된 현금성 항목이면 false를 돌려준다.
  - 자동 납입 판정의 만기 조건도 같은 판단을 쓰게 맞춰 규칙을 한 곳에 둔다.
  - 장점: 판정 결과를 쓰는 화면 5곳이 함께 정리된다. API·DB 변경이 없다. 단위 테스트로 확인할 수 있다.
- **B. 화면에서만 걸러내기**
  - 리마인더·배지·안내마다 만기 확인을 넣는다.
  - 단점: 사용처가 5곳이라 빠뜨리기 쉽고, 서버 응답의 미납 값과 화면이 어긋난다.

### 2. 만기 지난 항목을 자동 납입으로 저장할 때 (작업 내용 2)
- **A. 안내만 (권장)**
  - 등록·수정 모달에서 자동 납입을 골랐고 만기일이 오늘이거나 지났으면 "만기일이 지나 자동 납입이 기록되지 않습니다." 안내를 보인다. 저장은 그대로 된다.
  - 장점: 자동 기록은 어차피 생기지 않으므로 해가 없다. API 변경이 없다.
- **B. 서버에서 막기(400)**
  - 저장할 때 만기가 지났으면 자동 반영을 거부한다.
  - 단점: 오늘 날짜(KST)를 도메인 검사에 넘겨야 한다. 이미 자동 반영인 만기 항목은 메모만 고쳐도 400이 나서 처리 방식부터 바꿔야 한다. API 오류 계약이 늘어난다.
- **C. 저장할 때 알림 확인으로 바꾸기**
  - 사용자가 고른 값을 몰래 바꾸므로 권장하지 않는다.

### 3. 만기 지난 자동 납입 항목의 설명 줄 (작업 내용 3)
- **A. "자동 납입"을 빼기 (권장)**
  - 만기된 항목(현지 날짜 기준 만기일 당일부터)은 설명 줄에 "자동 납입"을 붙이지 않는다. 만기 상태는 표의 D-day·"만기 경과"와 설명 줄의 만기 날짜로 보인다.
- **B. "자동 납입(만기)"처럼 바꿔 보이기**
  - 설정은 보이지만 한 줄 말줄임 안에서 줄이 길어진다.
- **C. 그대로 두기**
  - 1번으로 미납 표시는 사라지지만, 기록되지 않는 "자동 납입"이 계속 보인다.

## 권장 접근
- 1A + 2A + 3A
  - 서버는 만기 판단을 도메인 한 곳에 두고 당일·미납 판정과 자동 납입 판정에서 함께 쓴다.
  - 화면은 만기된 자동 납입 항목에 안내를 보이고 설명 줄 표시를 맞춘다.
  - DB·Entity·API 변경이 없다.
- 날짜 기준: 서버 판정은 KST 날짜(#138과 같다), 화면 표시·안내는 브라우저 현지 날짜(기존 "만기 경과" 계산과 같다)를 쓴다.
