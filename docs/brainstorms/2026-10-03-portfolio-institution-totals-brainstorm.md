## 요청 이해
자산을 등록·수정할 때 은행(금융기관)을 따로 입력하는 칸을 두고, 보유 자산을 금융기관별로 묶어 총액을 보여 준다.

## 문제 정의
- 자산에 금융기관을 기록하는 칸이 없다. 연금만 "운용사" 칸이 있다.
- 지금은 항목명에 은행 이름을 넣는 방법뿐이라, 기관별로 얼마가 있는지 볼 수 없다.

## 목표
- 자산을 등록·수정할 때 금융기관을 입력할 수 있다.
- 보유 자산 목록에서 각 항목의 금융기관이 보인다.
- 금융기관별 총액과 비중을 한눈에 본다. 금융기관을 입력하지 않은 자산은 "미지정"으로 묶는다.

## 범위
- 백엔드: 포트폴리오 항목에 금융기관 값 저장(컬럼 추가), 등록·수정 요청과 항목 응답에 필드 추가
- 프론트: 등록·수정 모달 입력칸, 보유 자산 목록 표시, 금융기관별 합계 화면

## 제외 범위
- 금융기관 목록 관리(관리자 등록·코드화), 은행 API 연동, 계좌번호 저장
- 매도 이력·스냅샷·알림·배당 집계 변경
- 기존 자산의 금융기관 자동 채우기(확인 3: 운용사 값을 옮기지 않는다)

## 현재 코드 확인 결과
- **공통 필드:** `PortfolioItem`에 항목명·자산군·투자 금액·리전·메모 등이 있다(`PortfolioItem.java:15-34`). 테이블은 `portfolio_item`이고 메모는 `memo VARCHAR(500)` nullable이다(`PortfolioItemEntity.java:48-49`).
- **등록·수정 흐름:** 자산군별 등록 7종·수정 7종 API가 각각 요청 DTO와 서비스 메서드를 갖는다. 메모가 모든 경로를 지난다(컨트롤러 `getMemo()` 19곳, `PortfolioService`의 등록·수정 메서드 14개). 도메인에는 `updateMemo` 같은 공통 수정 메서드가 있다(`PortfolioItem.java:246`).
- **자산군별 상세:** 예금·적금·CMA(`CashDetail`), 주식(`StockDetail`), 채권, 펀드, 부동산, 금, 연금 모두 금융기관 칸이 없다. 연금만 `PensionDetail.provider`("운용사", 예: 미래에셋)가 있고 목록 설명 줄에 보인다(`portfolio-add.html:249-250`, `portfolio.js:1048`).
- **연결 현금 자산:** 주식은 CMA 같은 현금성 자산을 고를 수 있고, 목록에 "연결 · {이름}" 배지가 붙는다(`portfolio-holdings.html:254-258`).
- **평가액·집계:** 화면이 `getEvalAmount(item)`로 평가액을 계산한다. 주식은 현재가 × 수량, 연금은 입력 평가액, 나머지는 원금이다(`portfolio.js:360`). 자산군 도넛과 그룹 합계도 화면에서 계산한다(`getHoldingGroups` `:802`, `renderDonutChart` `:988`).
- **보유 자산 탭:** KPI 4장 → 자산 추이 + 자산군 구성(도넛) → 보유 자산 테이블 순서다(`portfolio-holdings.html`).
- **DB:** `ddl-auto: update`라 nullable 컬럼 추가는 자동 반영된다(#110 확인 사실). 스키마 변경은 `src/main/resources/db/migration`에 SQL로 남기는 관례가 있다.

## 후보 접근
- **A. 포트폴리오 항목 공통 필드로 금융기관을 둔다(`portfolio_item`에 nullable 컬럼 1개).**
  - 장점: 모든 자산군이 같은 칸을 쓰고 집계 키가 하나다. 메모와 같은 흐름이라 구조가 단순하다.
  - 단점: 등록·수정 14개 경로의 요청 DTO와 서비스 메서드를 모두 고친다.
- **B. 자산군 상세마다 칸을 둔다(예금은 은행, 주식은 증권사 등).**
  - 장점: 자산군별 의미가 정확하다.
  - 단점: 컬럼이 여러 테이블에 흩어지고, 집계 때 다시 합쳐야 한다.
- **C. 공통 필드 + 별도 수정 API(등록 후 한 번 더 호출).**
  - 장점: 기존 메서드를 덜 고친다.
  - 단점: 저장이 두 번에 나뉘어 한쪽만 실패할 수 있고 화면 로직이 복잡해진다.

## 권장 접근
A를 권장한다.
- `portfolio_item`에 금융기관 컬럼(가칭 `institution`, VARCHAR(50) NULL)을 추가한다. 앞뒤 공백을 지우고 빈 값은 null로 저장한다.
- 등록·수정 요청 DTO 14종과 항목 응답에 필드를 추가하고, 도메인에 금융기관 수정 메서드를 둔다.
- 기관별 합계는 화면에서 계산한다(자산군 도넛과 같은 방식, 새 API 없음).

- 금융기관별 총액을 보여 준다.

## 태형님 확인 필요
1. **칸 이름과 대상 자산군**
   - 권장: "금융기관"(예: 국민은행, 키움증권, 업비트)으로 하고 모든 자산군에 둔다.
   - 대안: "은행"으로 하고 예금·적금·CMA·펀드 같은 금융자산에만 둔다.
2. **입력 방식**
   - 권장: 직접 입력하되, 이미 입력한 기관명을 자동 완성으로 제안한다. 같은 기관이 다른 이름으로 갈라지는 것을 줄인다.
   - 대안: 정해진 목록에서 고른다(목록 관리가 필요하다).
3. **연금 "운용사" 처리**
   - 권장: 그대로 두고 금융기관은 따로 입력한다. 의미가 분리되고 데이터 이관이 없다.
   - 대안 1: 금융기관이 비어 있으면 집계에서 운용사로 묶는다.
   - 대안 2: 운용사 값을 금융기관으로 한 번 옮기고 운용사 칸을 없앤다(데이터 이관).
4. **합계 기준과 위치**
   - 권장: 평가액 기준. 보유 자산 탭의 "자산 추이·자산군 구성" 아래에 "금융기관별 합계" 카드를 둔다. 기관명·항목 수·평가액·비중 막대를 금액 큰 순으로 보이고 "미지정"은 마지막에 둔다.
   - 대안: 자산군 구성 도넛에 "자산군/금융기관" 전환을 넣거나 분석 탭에 둔다. 원금 기준으로 한다.
5. **목록 표시**
   - 권장: 보유 자산 테이블의 항목명 옆에 금융기관을 작게 표시한다.
6. **연결 현금 자산 상속**
   - 권장: 상속하지 않는다. 주식도 자기 칸에 입력한다.
   - 대안: 주식의 금융기관이 비어 있으면 연결된 현금 자산의 금융기관을 따른다.
7. **진행 방식**
   - 권장: 세션 브랜치와 하네스 절차를 따른다. 단위 테스트는 금융기관 값 정규화(공백·길이)와 저장 경로에 상태 기반으로 작성한다. DB는 nullable 컬럼 추가로, plan의 DB 스키마 리뷰에서 테이블 설계를 확정한다.
