# 주식 매도 실입금액 보정

## Summary

주식 매도 기록에 총 체결금액과 실입금액을 분리해 저장하고, 세금·수수료 같은 차감액 또는 사용자가 확인한 최종 입금액을 반영할 수 있게 한다. 목표는 기존 매도 기능의 사용자 입력 SoT 원칙을 유지하면서 증권사 체결 내역, 예수금 입금액, 외부 기록과의 금액 오차를 줄이는 것이다.

---

## Problem Frame

현재 매도 흐름은 매도 수량과 판매 단가를 기준으로 총 판매금액을 계산하고, 그 금액을 매도 이력과 CASH 입금에 사용한다. 실제 증권사 기록에서는 매도 체결금액에서 위탁수수료, 거래세, 농특세, SEC fee, 환전·해외 제비용 등이 차감되어 예수금에 들어오는 금액이 달라질 수 있다.

사용자는 단가와 수량을 정확히 입력해도 매도 이력의 금액과 실제 입금액이 맞지 않는 상황을 겪는다. 세금·수수료를 계산해서 맞추는 방식만으로는 증권사별 반올림, 통화, 정산 시점, 기타 제비용 차이를 완전히 흡수하기 어렵다. 따라서 이 기능은 세금 계산기를 만드는 것이 아니라, 사용자가 외부 기록과 맞춘 최종 금액을 남길 수 있는 정정 가능한 기록 체계를 목표로 한다.

---

## Actors

- A1. 포트폴리오 사용자: 실제 증권사 매도 내역을 보고 포트폴리오 매도 기록을 입력·정정한다.
- A2. 외부 기준 기록: 증권사 체결 내역, 예수금 입금액, 거래내역서처럼 사용자가 맞춰 보려는 원천 기록이다.
- A3. 후속 계획/구현 에이전트: 기존 매도 기능과 충돌하지 않게 요구사항을 구현 단위로 분해한다.

---

## Key Flows

- F1. 매도 등록 시 실입금액 보정
  - **Trigger:** 사용자가 보유 주식에서 매도 등록 모달을 연다.
  - **Actors:** A1, A2
  - **Steps:** 사용자는 기존처럼 수량, 판매 단가, 매도일을 입력한다. 화면은 총 체결금액을 계산한다. 사용자는 증권사 기록에 맞춰 차감액 또는 최종 실입금액을 입력한다. 저장 후 매도 이력에는 체결 기준 금액과 실입금 기준 금액이 함께 남는다.
  - **Outcome:** 매도 이력의 CASH 입금 기준 금액이 외부 예수금 입금액과 최대한 맞는다.
  - **Covered by:** R1, R2, R3, R4, R6, R7

- F2. 매도 이력 사후 정정
  - **Trigger:** 사용자가 매도 후 실제 정산금 또는 거래내역서 금액이 다르다는 것을 확인한다.
  - **Actors:** A1, A2
  - **Steps:** 사용자는 매도 이력 상세에서 기존 수량·단가뿐 아니라 차감액 또는 실입금액을 수정한다. 시스템은 표시 금액, 손익, CASH 반영액을 다시 맞춘다.
  - **Outcome:** 이미 저장된 매도 기록도 실제 외부 기록에 맞게 정정된다.
  - **Covered by:** R8, R9, R10, R11

---

## Requirements

**금액 모델**
- R1. 매도 이력은 총 체결금액과 실입금액을 구분해서 보여줘야 한다. 총 체결금액은 기존 판매 단가 × 수량 × 환율 기준의 거래 규모이고, 실입금액은 세금·수수료 등 차감 후 사용자가 실제로 받은 금액이다.
- R2. 사용자는 매도 등록 시 추가 차감액을 입력할 수 있어야 한다. 차감액은 세부 항목이 없어도 하나의 합계로 입력 가능해야 한다.
- R3. 사용자는 계산된 차감 후 금액이 실제 기록과 다를 때 최종 실입금액을 직접 수정할 수 있어야 한다.
- R4. 실입금액이 직접 입력된 경우 그 값이 CASH 입금과 매도 이력의 정산 기준 SoT가 되어야 한다.
- R5. 총 체결금액은 기존 매도 단가 기반 손익 계산과 거래 규모 확인을 위해 계속 보존되어야 한다.

**오차 최소화 UX**
- R6. 화면은 총 체결금액, 차감액, 실입금액을 한 흐름에서 같이 보여줘야 한다.
- R7. 실입금액이 총 체결금액과 다르면 차이 금액을 명확히 보여줘야 한다.
- R8. 매도 이력 상세 화면에서도 총 체결금액, 차감액, 실입금액을 확인할 수 있어야 한다.
- R9. 매도 이력 수정 화면은 기존 수량·판매 단가·사유·메모뿐 아니라 차감액 또는 실입금액 수정도 허용해야 한다.
- R10. 수정 저장 후 월별 매도 이력 합계와 해당 CASH 잔액은 수정된 실입금액 기준으로 일관되게 반영되어야 한다.

**손익 기준**
- R11. 수익금·수익률은 사용자가 외부 기록과 맞추려는 값이 무엇인지 혼동하지 않도록 체결 기준 손익과 실입금 기준 손익의 의미를 구분해야 한다.
- R12. 기본 실현 손익 표시는 실입금액 기준을 우선해야 한다. 사용자가 실제로 받은 금액과 포트폴리오 현금 흐름을 맞추는 것이 이번 이슈의 핵심이기 때문이다.
- R13. 기존 매도 기능의 사용자 입력 SoT 원칙은 유지한다. 시장가, 자동 세율, 추정 수수료는 보조값일 수 있지만 최종 정산 기준은 사용자가 입력 또는 확인한 값이어야 한다.

**기존 기능 호환**
- R14. 기존 매도 등록 흐름은 차감액을 입력하지 않아도 계속 동작해야 한다. 이 경우 실입금액은 총 체결금액과 동일하게 간주한다.
- R15. 기존 매도 이력은 보정값이 없어도 조회와 수정이 가능해야 한다. 과거 데이터는 총 체결금액과 실입금액이 같은 기록으로 해석한다.
- R16. 해외 주식은 기존 환율 입력·자동 조회 흐름과 충돌하지 않아야 한다. 실입금액은 사용자가 맞추려는 기준 통화가 KRW인지 원통화인지 planning 단계에서 명확히 정한다.

## Acceptance Examples

- AE1. **Covers R1, R2, R4, R14.** Given 사용자가 10주를 주당 10,000원에 매도하고 차감액 500원을 입력하면, 총 체결금액은 100,000원으로 남고 실입금액과 CASH 입금액은 99,500원이 된다.
- AE2. **Covers R3, R4, R7.** Given 자동 계산된 실입금액이 99,500원이지만 증권사 예수금 입금액이 99,480원이면, 사용자는 실입금액을 99,480원으로 직접 수정할 수 있고 화면은 총 체결금액과의 차이를 보여준다.
- AE3. **Covers R8, R9, R10.** Given 저장 후 실제 거래내역서에서 수수료가 다르게 확인되면, 사용자는 매도 이력 상세에서 실입금액을 수정하고 월별 합계와 CASH 잔액은 수정된 금액 기준으로 갱신된다.
- AE4. **Covers R11, R12.** Given 총 체결 기준으로는 손익이 10,000원이지만 세금·수수료 차감 후 실제 손익이 9,200원이면, 기본 실현 손익 표시는 9,200원을 우선 표시하되 체결 기준 금액도 확인 가능해야 한다.

## Success Criteria

- 사용자는 증권사 매도 내역의 총 체결금액과 예수금 실입금액을 모두 포트폴리오 매도 이력에 남길 수 있다.
- 매도 후 CASH 잔액이 실제 계좌 예수금 흐름과 더 가깝게 맞는다.
- 매도 이력에서 계산값과 실제값이 다를 때 사용자가 삭제 후 재등록하지 않고 정정할 수 있다.
- 기존 매도 기능의 단가·수량 기반 기록, 전량/부분 매도, 매도 이력 조회·수정 흐름이 깨지지 않는다.
- 계획 단계에서 세금 자동 계산 범위가 아니라 사용자 정정 가능한 실입금액 모델로 구현 방향을 잡을 수 있다.

---

## Scope Boundaries

- 포함: 주식 매도 등록과 매도 이력 수정에서 차감액 또는 실입금액을 반영하는 요구사항.
- 포함: 매도 이력 목록·상세·월별 합계에서 체결 기준 금액과 실입금 기준 금액을 구분하는 요구사항.
- 포함: CASH 입금 기준을 총 판매금액이 아닌 실입금액으로 맞추는 요구사항.
- 제외: 증권사별 세금·수수료 자동 계산기.
- 제외: 외부 증권사 거래내역 자동 연동.
- 제외: FIFO, 양도소득세 신고, 연간 세금 리포트.
- 제외: 주식 외 자산의 매각·환매·인출 정산 모델.

---

## Key Decisions

- 실입금액을 SoT로 둔다: 오차 최소화의 최종 기준은 계산식이 아니라 사용자가 외부 기록에서 확인한 실제 정산 금액이다.
- 총 체결금액은 보존한다: 매도 단가 기반 분석과 기존 손익 계산 맥락을 유지하려면 체결 기준 금액도 필요하다.
- 세금·수수료는 합계 입력을 우선한다: 세부 항목 분해는 정확해 보이지만 증권사·시장·통화별 예외가 많아 초기 목표인 오차 최소화에는 직접 입력 합계가 더 실용적이다.
- 기존 매도 흐름은 깨지지 않아야 한다: 차감액을 입력하지 않는 사용자는 기존과 같은 방식으로 저장할 수 있어야 한다.
- 사후 수정은 필수다: 실제 정산금은 매도 직후가 아니라 나중에 확인되는 경우가 있으므로 등록 시점 입력만으로는 오차를 줄이기 어렵다.

## Dependencies / Assumptions

- 현재 매도 기능은 이미 `docs/brainstorms/2026-04-26-portfolio-stock-sale-requirements.md`의 원칙을 기반으로 한다.
- 현재 코드에는 매도 수량, 판매 단가, 환율, 매도 이력 수정 흐름이 존재한다.
- 현재 확인된 흐름에서는 세금·수수료 차감액 또는 최종 실입금액을 별도로 입력·저장하는 요구사항이 없다.
- 외부 기준 기록은 사용자가 수동으로 확인한다고 가정한다. 자동 연동은 본 범위가 아니다.
