## 이슈 상세 기반 이해
새 기업 리포트를 쓰다가 1단계로 돌아가 다른 종목을 고르면, 이전 종목 기준으로 채운 S-RIM 입력과 채권 기준수익률 선택 상태가 그대로 남는다. 종목이 바뀌면 이 상태를 비운다. 같은 종목을 다시 고르거나 수정·재개 모드일 때는 유지한다. 저장된 S-RIM 데이터와 계산식은 바꾸지 않는다.

## 문제 정의
- 이전 종목의 지배주주지분·유통주식수·기준일·요구수익률·ROE 연도 행이 새 종목 S-RIM에 섞인다. 모르고 계산하거나 저장하면 잘못된 적정주가가 리포트에 남는다.
- 특히 원화 종목에서 적용한 채권 기준수익률이 외화(USD) 종목 S-RIM에 남는다. #131에서는 경고 문구만 붙였다.

## 목표
- 새 리포트 작성 중 종목이 바뀌면 S-RIM 입력과 채권 기준수익률 선택 상태를 비운다.
- 같은 종목을 다시 고르면 그대로 둔다. 수정·재개 모드의 입력도 그대로 둔다.

## 범위
- 기업 리포트 화면의 종목 선택 흐름(`company-report.js`, 확인 3에 따라 `company-report.html`)
- 초기화 대상
  - S-RIM 입력 전체: 금액 단위, 지배주주지분·기준일, 유통주식수·기준일, 요구수익률, 비교 기준 주가·기준일, ROE 연도 행
  - 자동 채움 추적과 출처 표시, 계산 결과·오류
  - 채권 기준수익률 선택 상태: 요청일, 조회 결과, 종류·등급·만기, 적용 근거

## 제외 범위
- 종목 평가 화면: 종목을 고를 때마다 이미 S-RIM을 초기화한다(`stock-eval.js:119`).
- S-RIM 외의 기업 리포트 입력(연혁·고객·경쟁사·판단 코멘트 같은 수기 입력, 등급, 가치평가 파라미터). 이 입력들도 종목을 바꾸면 남지만 이슈 범위 밖이다.
- 백엔드, 저장 구조, 계산식, 이미 저장된 리포트 데이터
- 수정·재개 모드의 종목 변경. 지금도 막혀 있다.

## 현재 코드 확인 결과
- **종목 선택:** `companyReportSelectStock(stock)`(`company-report.js:633`)은 `selected`를 바꾸고 검색 결과를 비운 뒤 공시와 미리보기만 다시 불러온다. S-RIM은 건드리지 않는다.
- **1단계 이동:** `companyReportGoStep(n)`(`company-report.js:785`)은 수정·재개(`mode === 'edit'`)에서 1단계 이동을 막는다. 그래서 수정·재개에서는 종목을 바꿀 수 없다.
- **첫 임시저장:** `_crPersist`(`company-report.js:994`)는 첫 저장 뒤 `mode`를 `edit`로 바꾼다. 따라서 종목 변경은 새 리포트 작성 중, 첫 임시저장 전에만 일어난다.
- **기존 초기화 함수:** `_crResetForm()`(`company-report.js:1067`)은 계산 세대 번호를 올리고 `srim`을 `_crSrimEmpty()`로 바꾼다. 하지만 수기 입력·등급·파라미터까지 모두 초기화한다. S-RIM만 비우는 함수는 없다.
- **늦게 끝나는 요청:**
  - S-RIM 계산은 세대 번호(`_crSrimGeneration`)로 늦은 결과를 버린다.
  - 채권 금리 조회는 `rate` 객체의 세대 번호로 늦은 응답을 버린다. `rate`를 새 객체로 바꾸면 이전 객체에 쓰인 응답은 화면에 나오지 않는다.
- **S-RIM 포함 여부:** S-RIM 영역은 5단계에 있고(`company-report.html:516~`) 포함 여부 체크(`srim.enabled`)가 있다. `_crSrimEmpty()`는 이 체크도 해제한다.
- **#131 USD 경고:** `crSrimRateAppliedNote()`(`company-report.js:315`)와 `company-report.html:749`에 있다. 적용 근거가 남은 채 통화가 USD로 바뀔 때만 보인다. 종목 변경 시 초기화하면 이런 상황이 생기지 않는다.

## 후보 접근
- **A. 종목 선택 시 종목 코드가 바뀌면 S-RIM만 초기화한다.** `companyReportSelectStock`에서 이전 종목 코드와 비교한다.
  - 장점: 변경 지점이 한 곳이다. 수정·재개 흐름에 영향이 없고, 같은 종목 재선택 판정이 단순하다.
  - 단점: 나중에 종목을 바꾸는 경로가 늘면 같은 처리를 붙여야 한다.
- **B. S-RIM 상태에 기준 종목을 저장하고, 5단계에 들어갈 때 현재 종목과 다르면 초기화한다.**
  - 장점: 종목이 어떤 경로로 바뀌어도 잡힌다.
  - 단점: 상태 필드와 비교 지점이 늘어난다. 지금은 경로가 하나뿐이라 과하다.
- **C. 초기화 전에 확인창을 띄워 사용자가 고르게 한다.**
  - 장점: 실수로 입력을 잃지 않는다.
  - 단점: 다른 종목을 고르는 것 자체가 명시적인 행동이고, 이전 종목 값을 유지할 이유가 없다. 다른 입력과 동작이 달라져 오히려 헷갈린다.

## 권장 접근
A를 권장한다.
- `companyReportSelectStock`에서 새 종목 코드가 현재 `selected.stockCode`와 다르면 S-RIM 전용 초기화 헬퍼를 호출한다.
- 헬퍼는 계산 세대 번호를 올리고 `srim`을 `_crSrimEmpty()` 기준으로 바꾼다. 포함 여부 체크 처리는 확인 1에 따른다.
- 같은 종목을 다시 고르면 아무것도 하지 않는다.
- 수정·재개 흐름과 `_crResetForm()`은 바꾸지 않는다.

## 결정 사항 (이슈에서 확정)
