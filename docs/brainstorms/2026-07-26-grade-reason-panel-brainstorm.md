## What We're Building

정량 5항목 각각의 제안 등급 옆에 화살표 아이콘을 추가하고, 클릭 시 우측 슬라이드 패널에서 아래 4개 섹션을 보여준다. 위저드 7단계와 상세 뷰 양쪽에서 진입 가능하다.

1. **산출 사유** — basis 지표들을 판정 색상(good=초록/warn=노랑/risk=빨강)과 함께 목록 표시
2. **등급 기준** — A~E 밴드 바에서 현재 밴드 하이라이트 + 기준 규칙 설명
3. **계산식** — 지표가 어떻게 계산됐는지 항 단위 식 (예: PBR = 시가총액 ÷ 자본총계 = 0.68배)
4. **원천 데이터** — 관련 재무제표 계정의 연도별 미니 표 (BS/IS/CF), 항목별로 관련 계정만

## 항목별 패널 구성

공통 헤더: 항목명 + 제안 등급 배지 + 닫기(X). 기준연도는 `snapshot.valuationInputs.baseYear` 표기.

### ① assetUndervalue — 자산으로 본 저평가
- 사유: 시가총액/청산가치 배수, PBR
- 기준: 청산가치 밴드(A ≤1.0 / B ≤1.5 / C ≤2.5 / D ≤4.0 / E 초과), PBR 밴드(B ≤0.6 / C ≤1.0 / D ≤2.0 / E 초과) — 유리한 쪽 채택 표시
- 계산식: PBR breakdown(`priceMetrics.breakdowns.pbr`), 청산가치 = 조정자산 합계 − 총부채, 시총/청산가치 배수
- 원천: `valuation.liquidation.lines` (카테고리별 장부가 × 인정비율 = 조정가 표) + 시가총액

### ② earningsUndervalue — 수익 창출 능력으로 본 저평가
- 사유: 시총/DCF보수, 시총/DCF낙관, PER
- 기준: DCF 밴드(A 보수≤1.0 / B 보수≤1.5 / C 낙관≤1.0 / D 낙관≤1.5 / E 초과), PER 밴드(B ≤8 / C ≤15 / D ≤25 / E 초과)
- 계산식: PER breakdown, DCF 보수 = 순현금 + FCF/r, 낙관 = 순현금 + n년 g성장 후 영구가치 할인 (`valuation.params`의 r·g·n 표기)
- 원천: 순현금·FCF(`valuationInputs`), DCF 보수/낙관 가치, 시가총액

### ③ financialHealth — 재무건전성
- 사유: 자기자본비율·유동비율·부채비율(판정) + 순현금
- 기준(규칙형): E: risk 2개↑ 또는 채무초과 / D: risk 1 / C: warn 있음(결손 포함) / B: 3종 모두 good / A: B + 순현금>0 + 위험 시그널 전부 false — 해당 규칙 하이라이트
- 계산식: 자기자본비율 = 자본총계 ÷ 자산총계, 유동비율 = 유동자산 ÷ 유동부채, 부채비율 = 부채총계 ÷ 자본총계 — `statements`의 BS 계정값으로 조립
- 원천: BS 연도별(자산총계·부채총계·자본총계·유동자산·유동부채) + 위험 시그널 상태

### ④ profitability — 수익성
- 사유: 영업이익률·ROE·ROA(판정)
- 기준(규칙형): E: 영업이익률 risk 또는 기준연도 ROE<0 / D: risk 있음 / C: warn 있음 / B: 3종 모두 good / A: B + ROE≥15%·영업이익률≥10% 최근 3개 연도 지속
- 계산식: 영업이익률 = 영업이익 ÷ 매출액, ROE = 당기순이익 ÷ 자본총계 — IS/BS 계정값으로 조립
- 원천: `ratios` 연도별 추이(영업이익률·ROE·ROA — A 지속성 확인용) + IS 연도별(매출액·영업이익·당기순이익)

### ⑤ growth — 성장성
- 사유: 매출 성장률, 영업이익 성장률(기준연도)
- 기준(규칙형): E: 둘 다 음수 2년 연속 / D: 한쪽 음수 / C: 둘 다 ≥0 / B: 둘 다 ≥10% / A: B + 최근 4개 연도 중 3개 연도 이상
- 계산식: 성장률 = (당년 − 전년) ÷ 전년 — IS 매출액·영업이익으로 조립
- 원천: 성장률 연도별 추이 + IS 연도별(매출액·영업이익)

## 검토한 대안 (채택 안 함)

- **안 1: 근거 칩 wrap 인라인 표시** — 한눈에 보이지만 카드 세로 공간 증가, 계산식·원천 데이터까지는 못 담음. 패널 방식이 정보량에서 우위.
- **안 2: 요약 뱃지 + 팝오버** — 공간 유지되나 정보량 한계 동일.
- **기준표 ②안: `GradeSuggestion` DTO에 밴드/기준 필드 추가** — 단일 소스 유지 장점이 있으나 API 응답 변경(승인 게이트 대상). 기준표가 자주 바뀌지 않아 ①로 결정.

## Edge Cases

- 제안 없는 항목(데이터 결손·정성 2항목) → 화살표 자체를 렌더링하지 않음.
- `priceMetrics.breakdowns`에 해당 지표가 없으면(중간값 결손) → 계산식은 공식 문자열만 표시 (기존 crBreakdownText 동작과 동일 원칙).
- 청산가치 ≤ 0, DCF 계산 불가(`dcf.calculable=false`) → 해당 식 대신 사유(`dcf.reason`) 표기.
- 구 스냅샷(계정 결손) → 원천 데이터 표에서 결손 행은 '—' 표시 (0 대체 금지).
- 모바일 폭 → 패널 전체폭 오버레이 (기존 슬라이드 패널 패턴의 반응형 동작 따름).

## 범위 밖 (하지 않음)

- 백엔드·API·Entity·DB 변경 (기준표 DTO 확장 포함 — 후속 후보).
- 기존 한 줄 근거 표시의 제거·변경 (패널 추가만, 기존 UI 불변).
- 정성 2항목 자동 제안.
- 기준치 파라미터화.
