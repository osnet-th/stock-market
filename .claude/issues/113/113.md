# #113 [enhancement] 포트폴리오 배당 집계를 KSD 실지급일 기준으로 전환 (#110 후속)

## 본문

## 배경

#110 에서 포트폴리오 상단에 "이달 배당 · 이자" KPI 를 추가하면서, 당초 계획은 **KSD 배당 일정(예탁원정보 API) × 보유 수량**으로 실제 지급 예정 배당을 집계하는 것이었다.

구현 단계에서 아래 이유로 **사용자 입력 시가배당률 기반**으로 대체했다.

- KSD 조회(`KisKsdScheduleClient.fetch(DIVIDEND, ...)`)는 **종목당 외부 API 1회**라 보유 종목 수만큼 지연·실패 위험이 붙는다
- 화면 진입마다 호출하기엔 비용이 크고, 실패하면 KPI 가 통째로 비어버린다

## 현재 동작 (#110 구현)

`PortfolioIncomeService`

| 항목 | 산출 |
|---|---|
| 주식 배당 (연 예상) | `StockDetail.dividendYield` × 평가액 |
| 예적금·CMA 이자 | 원금 × `CashDetail.interestRate` |
| 채권 이자 | 원금 × `BondDetail.couponRate` |
| **이달 금액** | **연 예상 ÷ 12 (월 평균 환산)** |
| 배당률·금리 미입력 항목 | 집계 제외, `excludedCount` 로 노출 |

응답의 `basis = ESTIMATED_MONTHLY_AVERAGE` 와 화면 캡션("월 평균 환산 기준")으로 기준을 노출하고 있다.

## 문제

**"이달 배당 · 이자"라는 라벨과 실제 의미가 일치하지 않는다.** 지금 값은 실제 이번 달 지급 예정액이 아니라 연 예상의 1/12 이다. 배당이 특정 월에 몰리는 국내 주식 특성상 실제 체감과 크게 어긋날 수 있다.

또한 `dividendYield` 는 사용자가 자산 등록 시 직접 입력하는 값이라 최신성이 보장되지 않는다.

## 하고 싶은 것

KSD 배당 일정을 실제로 활용해 **지급일 기준** 집계로 전환한다.

- [ ] 국내 주식: `KsdScheduleType.DIVIDEND` 로 `divi_pay_dt`(배당금지급일) 과 `per_sto_divi_amt`(현금배당금) 조회 → 보유 수량과 곱해 이달 지급 예정액 산출
- [ ] 조회 결과 캐싱 — 배당 일정은 자주 바뀌지 않으므로 종목별·기간별 캐시(또는 배치 적재)로 화면 진입마다 외부 호출이 나가지 않게 한다
- [ ] 연 예상은 최근 1년 실지급 이력 기준으로 전환할지, 현행 `dividendYield` 기반을 유지할지 결정
- [ ] 해외 주식 배당 소스 검토 (현재 대응 소스 없음 — 계속 제외할지 결정)
- [ ] KSD 조회 실패 시 폴백 정책 — 현행 `dividendYield` 기반으로 떨어뜨리고 `basis` 로 구분
- [ ] `basis` 코드 확장 (`ACTUAL_PAYMENT_DATE` 등) 및 화면 캡션 반영
