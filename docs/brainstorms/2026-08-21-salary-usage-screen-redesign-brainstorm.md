## 목업 분석 (번들에서 추출한 template + DCLogic 스크립트 기준)

### 화면 구성
1. 헤더 행: 제목 `월급 사용 비율` · 월 전환(`‹ 2026-08 ›`) · 상속 출처/미저장 변경 노트 ·
   `예산 열 숨기기/예산 대비 보기` 토글 · `지난달 복사` · `+ 새 월 기록`
2. 요약 카드 3장
   - 월 실수령액(인라인 입력) + 배분됨/미배분(초과) + 카테고리 배분 리본 + 범례
   - 저축률 다크 카드: 저축률 % · 전월 대비 %p · 목표(50%) 대비 진행 바 · 보조 노트
   - 고정비/변동비 카드: 비율 · 이중 바 · 금액 요약
3. 사용처 계층 테이블
   - 카테고리 행: 접기/펼치기 caret · 색 칩 · 종류 배지(저축/고정/변동 포함) · 항목 수 ·
     금액(항목 있으면 합계 자동 계산=읽기전용, 없으면 직접 입력) · 비율 · 월급 대비 바 ·
     예산 입력 + 예산 대비 diff(±N만) · `+ 항목`
   - 하위 항목 행: 이름 입력 · 고정/변동 토글 · 금액 입력 · 카테고리 내 비중 % · 바 ·
     월급 대비 % · 삭제
   - 하단 미배분/초과 행
   - 모두 펼치기/모두 접기 · footer: 미저장 안내 + `되돌리기` + `변경 저장(저장됨)`
4. 하단: 최근 12개월 추이(모드 3종: 비율=저축률+목표선 / 금액=월급 점선+지출 실선 /
   구성=카테고리 비중 스택 영역) · `지난달 대비` 카테고리 diverging 바(상위 6) ·
   `눈에 띄는 것` 인사이트 3장(예산 초과 최대 / 저축률 목표 달성 여부 / 고정비 비중)

### 목업 데이터 모델 (DCLogic state)
- salary(월 실수령액), cats[] = { id, name, color, budget, items[] = { name, v, fixed } }
- 카테고리 금액 = items 합계(있으면) / flat 직접 입력(없으면)
- 저축률 = 저축·투자 카테고리 합 / salary, 목표 50%
- 고정비/변동비 = 항목 fixed 플래그 합산 (항목 없는 flat 금액은 미포함 — 목업 로직 그대로)
- 저장 모델: dirty 추적 + `변경 저장` 일괄 저장 + `되돌리기`

## 현재 구현과의 차이 (부족한 기능)

| 목업 기능 | 현재 백엔드 | 판단 |
|---|---|---|
| 카테고리 하위 항목(이름·금액·고정/변동) | 없음 (카테고리 금액+메모만) | 신규 모델 필요 |
| 카테고리별 예산 + 예산 대비 | 없음 | spending_config에 budget 추가 |
| 일괄 저장(항목·금액·예산 동시) | 카테고리/월급 개별 upsert | 배치 저장 API 신설 |
| 전월 대비 카테고리 증감·저축률 delta | 없음 | 월별 응답에 previous 요약 포함 |
| 추이 `구성` 모드(카테고리 비중 스택) | trend에 월급/총지출/저축률만 | TrendPoint에 categoryTotals 추가 |
| 지난달 복사 | 상속 모델이 암묵 제공 | 프론트에서 전월 유효값을 편집 버퍼로 복사 후 일괄 저장 |
| 커스텀 카테고리 추가/삭제 | SpendingCategory enum 8종 고정 | 이번 범위 제외 (아래 결정) |

## 결정 사항

1. 변경 지점(Effective Date) 상속 모델은 유지한다. 월급/카테고리 금액의 기존 테이블·NOOP
   의미론을 그대로 계승한다.
2. 하위 항목은 **월 단위 스냅샷 세트**로 모델링한다: `spending_item_set`(user, effective_from_month)
   1건이 그 달 이후의 전체 항목 구성을 나타내고, `spending_item`이 세트에 속한다
   (category · name · amount · fixed · sort_order). 상속 조회는 `effective_from_month <= 대상월`
   중 최신 세트. 빈 세트 = "이 달부터 항목 없음"을 명시 표현.
3. 항목이 있는 카테고리의 `spending_config.amount`는 **항목 합계(파생값)** 를 저장한다.
   → 기존 trend/합계 로직이 항목 인지 없이 그대로 정확하게 동작한다.
4. `spending_config`에 `budget`(nullable) 컬럼 추가. ddl-auto=update가 신규 테이블/컬럼을
   생성하므로 별도 수동 마이그레이션은 불필요.
5. 배치 저장 API `PUT /api/salary/monthly/{yearMonth}` 신설 — income + 카테고리(금액·예산) +
   항목 세트를 한 트랜잭션으로 upsert(NOOP 의미론 유지), 응답은 갱신된 월별 뷰.
6. 기존 개별 upsert/delete 엔드포인트는 하위 호환을 위해 유지한다 (신규 UI는 미사용).
7. 커스텀 카테고리 추가/삭제(목업의 `+ 카테고리`, 카테고리 ×)는 **이번 범위에서 제외**.
   - 근거: category가 `@Enumerated(EnumType.STRING)`으로 전 도메인에 박혀 있어 사용자 정의
     카테고리는 enum→테이블 전환 + 기존 데이터 이관이 필요한 별도 이슈 규모.
   - 목업의 시드 카테고리 8종이 기존 enum 8종과 정확히 일치하므로 화면 가치의 대부분은
     계층 항목·예산·일괄 저장으로 충족된다. 후속 이슈로 분리 제안.
8. 차트는 Chart.js 대신 목업과 동일한 SVG 직접 렌더(문자열 생성 후 x-html 주입)로 구현.
   도넛/바 차트는 목업에 없으므로 제거.
9. 저축률 목표는 프론트 상수 50%로 시작 (목업 defaultTrend/savingTarget props 대응).
