# 홈 대시보드 경제 대시보드형 리디자인 Brainstorm

## 문제 정의

태형님이 제시한 목업(`~/Downloads/경제 대시보드 리디자인 (단일파일).html`)대로 홈 대시보드를 재설계한다.

현재 홈(`partials/home.html`, 496줄)은 세 덩어리가 세로로 쌓여 있다.
1. 기능 요약 3카드 (뉴스 기록 · 월급 사용 비율 · 운영자 로그)
2. 요약 카드 4장 (키워드 · 국내 경제지표 · 글로벌 경제지표 · 포트폴리오)
3. 국내/글로벌 관심 지표 — 각각 "그래프 모드" 그리드와 "지표 모드" 가로 스크롤로 2분할

목업은 이걸 **"오늘의 시장" 단일 화면**으로 재구성한다. 지표 비교가 화면 중심에 오고,
알림·뉴스·월급이 우측 패널로 빠진다.

## 목업 구조 (추출 결과)

번들 HTML(React + `x-dc` 템플릿). 템플릿 296KB / 로직 13KB를 추출해 대조했다.

```
┌─사이드바(기존)─┬─────────── 메인 ───────────┬── 우측 320px ──┐
```

포트폴리오 요약은 헤더 우측에 다크 카드로 붙는다(총 평가액 · 안전/투자 비율 · 배분 밴드 초과 뱃지).

### 지표 카드 구성 (목업)
지표명 · 분류 · **큰 값** · 일간 델타(▲▼) · **스파크라인** · 기간 변화율 · 기준일 · 별표(비교 선택)

별표를 누르면 상단 비교 차트에 겹쳐진다. 선택 색은 순서대로 BLUE → RED → AMBER, 최대 3개이며
4개째를 누르면 가장 오래된 선택이 밀려난다.

### 비교 보기 정규화 2모드
- **변화율(%) 기준**: 기간 시작점을 0%로 맞춰 단위가 다른 지표를 같은 축에서 비교
- **자체 스케일 기준**: 각 지표를 자기 min~max로 정규화해 모양만 비교

## 현재와의 차이

| 영역 | 목업 | 현재 |

| 레이아웃 | 2단 (메인 + 우측 320px) | 단일 컬럼 |
| 헤더 | `오늘의 시장` + 기준시각 + 기간 버튼 + 모드 토글 | `대시보드` 제목만 |

| 우측 패널 | 알림 · 키워드 뉴스 · 월급 스택바 | 없음 |
| 기능 요약 3카드 | 없음 | 있음 |
| 요약 카드 4장 | 없음 | 있음 |
| 최근 업데이트 박스 | 없음 | 있음 |

## 데이터 충족도 조사

**대부분 프론트 계산으로 충족된다.** `GET /api/favorites/enriched` 가 이미
`history` · `dataValue` · `previousDataValue` · `cycle` · `className` · `unit` 을 반환한다.

| 목업 요소 | 데이터 출처 | 신규 필요 |
|---|---|---|
| 비교 차트 | `enriched.history` | 없음 |
| 스파크라인 | `enriched.history` | 없음 (단, 아래 제약) |
| 일간 델타 | `dataValue` vs `previousDataValue` | 없음 |
| 오늘 브리핑 | 위와 동일 | 없음 |
| 지표 추세 알림 | `history` 로 연속 상승 판정 | 없음 |
| 배분 밴드 초과 알림 | `homeSummary.allocationStatus` | 없음 |
| 예금 만기 D-day 알림 | 포트폴리오 항목 만기일 | 없음 |
| 월급 스택 바 | `dashboardSummary.salary.spendings` | 없음 (표현만 변경) |
| **키워드 뉴스 목록** | `GET /api/news` 가 `keywordId` **필수** | **통합 엔드포인트 필요** |

### 제약 1 — history 는 GRAPH 모드에만 붙는다
`FavoriteIndicatorService.attachEcosHistoryIfGraph()` 가 `displayMode != GRAPH` 이면 history 없이 통과시킨다.
표시 모드를 없애면 **전 항목에 history 가 필요**해지므로 이 분기를 제거해야 하고,
관심 지표 수만큼 시계열 조회가 늘어난다 → 배치 조회 또는 조회 건수 제한 검토 필요.

### 제약 2 — 키워드 뉴스
`NewsController` 의 `GET /api/news` 는 `@RequestParam Long keywordId` 가 필수다.
목업의 "13개 키워드 · 오늘 43건 + 최신 4건"을 그리려면 키워드 수만큼 호출해야 한다.

## Open Questions → 태형님 회신 (2026-08-17)

1. **표시 모드(displayMode)를 없앨지** — 목업은 모든 카드가 스파크라인 한 형태다.
   → **폐지 확정.** "표시 모드 없애고"
2. **키워드 뉴스 통합 목록** — 프론트 N회 호출 vs 신규 엔드포인트
   → **통합 엔드포인트 신설 확정.** "키워드 뉴스는 통합 엔드포인트로 만들자"
3. **기존 홈 섹션 처리** — 기능 요약 3카드 · 요약 카드 4장 · 최근 업데이트 박스
   → **목업대로 제거 확정.** "목업대로 없애줘"
   - 운영자 로그 카드는 `_sidebar.html` 에 admin 전용 메뉴로 이미 있어 접근 경로가 유지된다(확인 완료)

## 리스크

- 표시 모드 폐지는 **저장된 사용자 설정을 버리는 변경**이다. `display_mode` 컬럼 처리(제거 vs 방치) 결정 필요 → plan에서 확정
- history 무조건 첨부로 `/api/favorites/enriched` 응답 시간·쿼리 수 증가
- 홈 진입 시 호출이 늘어난다(favorites · allocation · salary · 키워드 뉴스) → 병렬화·부분 실패 흡수 유지 필요
- 목업은 지표 12종 고정 데이터 기준이라, 관심 지표가 0개이거나 20개 이상일 때의 레이아웃이 정의되어 있지 않음 → 빈 상태·과다 상태 규칙을 plan에서 정의
